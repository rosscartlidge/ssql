## Installation

### Standard Installation (CPU only)

```bash
# codelab: skip — installation (run once by hand)
# Install ssql - works on any system
go install github.com/rosscartlidge/ssql/v4/cmd/ssql@latest

# Verify installation
ssql version
```

All signal processing commands work immediately with CPU. GPU acceleration is optional but provides significant speedups for large datasets.

### GPU-Accelerated Installation (10-50x faster)

**Requirements:**
- NVIDIA GPU with CUDA support
- Docker with nvidia-container-toolkit, OR CUDA Toolkit installed locally

**Method 1: Docker Build (Recommended - no local CUDA needed)**

```bash
# codelab: skip — GPU build needs Docker + nvidia-container-toolkit
# Clone the repository
git clone https://github.com/rosscartlidge/ssql.git
cd ssql

# Build and extract the GPU-enabled binary
make docker-gpu-extract

# Install the library system-wide
sudo cp libssqlgpu.so /usr/local/lib && sudo ldconfig

# Install the binary
cp ssql_gpu ~/go/bin/

# Verify GPU is detected
ssql_gpu version
# Output: ssql vX.Y.Z (gpu: yes)
```

**Method 2: Local CUDA Toolkit Build**

```bash
# codelab: skip — GPU build needs a local CUDA toolkit
# Clone the repository
git clone https://github.com/rosscartlidge/ssql.git
cd ssql

# Build the CUDA library
cd gpu && make && cd ..

# Build ssql with GPU support
go build -tags gpu -o ssql_gpu ./cmd/ssql

# Install to your Go bin directory
sudo make install-gpu  # Installs libssqlgpu.so to /usr/local/lib
cp ssql_gpu ~/go/bin/

# Verify GPU is detected
ssql_gpu version
```

**When is GPU faster?**

| Operation | GPU Threshold | Speedup |
|-----------|---------------|---------|
| FFT/IFFT | ≥16K samples | 28-54x |
| Convolution | ≥16 point kernel | 4-500x |
| Correlation | ≥16 point window | 4-500x |

Below these thresholds, CPU is used automatically (faster due to transfer overhead).

## Understanding Signal Data

ssql processes signals as records with numeric fields. Each record represents one sample point.

### Creating Test Signals

**Simple sine wave:**
```bash
# Generate 1024 samples of a 10 Hz sine wave (at 1000 Hz sample rate)
python3 - > sine_wave.csv <<'EOF'
import math
print("time,amplitude")
for i in range(1024):
    t = i / 1000.0
    print(f"{t:.6f},{math.sin(2 * math.pi * 10 * t):.6f}")
EOF

# View the signal
ssql from sine_wave.csv | ssql limit 10 | ssql to table
```

**Multi-frequency signal (more interesting for FFT):**
```bash
# 10 Hz + 50 Hz + 120 Hz components
cat > generate_signal.py << 'EOF'
import math
print("time,amplitude")
for i in range(4096):
    t = i / 1000.0  # 1000 Hz sample rate
    amp = (math.sin(2 * math.pi * 10 * t) +      # 10 Hz
           0.5 * math.sin(2 * math.pi * 50 * t) +  # 50 Hz
           0.3 * math.sin(2 * math.pi * 120 * t))  # 120 Hz
    print(f"{t:.6f},{amp:.6f}")
EOF

python3 generate_signal.py > multi_freq.csv

# Visualize the time-domain signal (first 500 samples)
ssql from multi_freq.csv | \
  ssql limit 500 | \
  ssql to chart -x time -y amplitude -output signal_time.html

echo "Open signal_time.html to see the signal"
```

## Frequency Analysis with FFT

The Fast Fourier Transform (FFT) converts time-domain signals to frequency-domain, revealing the frequency components.

### Basic FFT

```bash
# Compute FFT of our multi-frequency signal
ssql from multi_freq.csv | \
  ssql fft -field amplitude -rate 1000 | \
  ssql limit 20 | ssql to table
```

Output shows frequency bins with their magnitudes (`_line_number` is the
row counter every ssql stream carries):
```
_line_number   frequency     index   magnitude
-----------------------------------------------------
           0             0       0             2.726159
           1   0.244140625       1   2.7284801528295475
...
          41   10.009765625     41   2042.974388801387    <- 10 Hz peak!
...
         205   50.048828125    205   957.9693360391922    <- 50 Hz peak!
...
         492    120.1171875    492   406.40466674290843   <- 120 Hz peak!
```

### Visualizing the Frequency Spectrum

```bash
# Create a frequency spectrum chart
ssql from multi_freq.csv | \
  ssql fft -field amplitude -rate 1000 | \
  ssql where -if frequency le 200 | \
  ssql to chart -x frequency -y magnitude -output spectrum.html

echo "Open spectrum.html to see the frequency spectrum"
```

The chart will show clear peaks at 10 Hz, 50 Hz, and 120 Hz - exactly the frequencies we put into the signal!

### Finding Dominant Frequencies

```bash
# Find the top 5 frequency peaks
ssql from multi_freq.csv | \
  ssql fft -field amplitude -rate 1000 | \
  ssql where -if frequency gt 1 | \
  ssql sort -desc magnitude | \
  ssql limit 5 | \
  ssql to table
```

### Including Phase Information

Phase tells you the offset of each frequency component:

```bash
# FFT with phase (needed for reconstruction via IFFT)
ssql from multi_freq.csv | \
  ssql fft -field amplitude -rate 1000 -phase | \
  ssql where -if frequency le 150 | \
  ssql limit 20 | ssql to table
```

## Frequency Domain Filtering

One of the most powerful signal processing techniques: transform to frequency domain, remove unwanted frequencies, transform back.

### Low-Pass Filter (Remove High Frequencies)

```bash
# Add noise to our signal first
cat > add_noise.py << 'EOF'
import math
import random
print("time,amplitude")
for i in range(4096):
    t = i / 1000.0
    clean = (math.sin(2 * math.pi * 10 * t) +
             0.5 * math.sin(2 * math.pi * 50 * t))
    noise = 0.3 * (random.random() - 0.5)  # High-frequency noise
    print(f"{t:.6f},{clean + noise:.6f}")
EOF

python3 add_noise.py > noisy_signal.csv

# View noisy signal
ssql from noisy_signal.csv | \
  ssql limit 500 | \
  ssql to chart -x time -y amplitude -output noisy.html

# Apply low-pass filter: FFT -> remove high frequencies -> IFFT
ssql from noisy_signal.csv | \
  ssql fft -field amplitude -rate 1000 -phase | \
  ssql where -if frequency le 100 | \
  ssql ifft -magnitude magnitude -phase phase | \
  ssql to chart -x index -y signal -output filtered.html

echo "Compare noisy.html and filtered.html"
```

### Band-Pass Filter (Keep Only Specific Frequencies)

```bash
# Keep only frequencies between 40-60 Hz (isolate the 50 Hz component)
ssql from multi_freq.csv | \
  ssql fft -field amplitude -rate 1000 -phase | \
  ssql where -if frequency ge 40 | \
  ssql where -if frequency le 60 | \
  ssql ifft -magnitude magnitude -phase phase | \
  ssql to chart -x index -y signal -output bandpass.html
```

### Notch Filter (Remove Specific Frequency)

```bash
# Remove 50 Hz (e.g., power line interference)
ssql from multi_freq.csv | \
  ssql fft -field amplitude -rate 1000 -phase | \
  ssql where -if-expr 'frequency < 48 || frequency > 52' | \
  ssql ifft -magnitude magnitude -phase phase | \
  ssql to chart -x index -y signal -output notch.html
```

## Smoothing with Convolution

Convolution applies a kernel (filter) to smooth, sharpen, or detect edges in signals.

### Moving Average Smoothing

```bash
# Create a noisy signal
cat > noisy_steps.py << 'EOF'
import random
print("index,value")
for i in range(1000):
    base = 0 if i < 300 else (50 if i < 600 else 25)
    noise = random.gauss(0, 5)
    print(f"{i},{base + noise:.2f}")
EOF

python3 noisy_steps.py > noisy_steps.csv

# View original noisy signal
ssql from noisy_steps.csv | \
  ssql to chart -x index -y value -output noisy_steps.html

# Apply 21-point moving average (the result lands in value_convolved)
ssql from noisy_steps.csv | \
  ssql convolve -field value -kernel avg -size 21 -same | \
  ssql to chart -x index -y value_convolved -output smoothed.html

echo "Compare noisy_steps.html and smoothed.html"
```

### Gaussian Smoothing

Gaussian smoothing provides smoother results than moving average:

```bash
# Apply Gaussian smoothing (sigma=5, size=21)
ssql from noisy_steps.csv | \
  ssql convolve -field value -kernel gaussian -size 21 -sigma 5 -same | \
  ssql to chart -x index -y value_convolved -output gaussian_smooth.html
```

### Edge Detection with Derivative Kernel

```bash
# Detect edges/transitions in the step signal: smooth, then differentiate
# (-output names the result field; the default is FIELD_convolved)
ssql from noisy_steps.csv | \
  ssql convolve -field value -kernel avg -size 11 -same -output smooth | \
  ssql convolve -field smooth -kernel diff -same -output edges | \
  ssql to chart -x index -y edges -output edges.html
```

### Custom Kernels

```bash
# Create a custom high-pass filter kernel
ssql from noisy_steps.csv | \
  ssql convolve -field value -custom "-1,-1,-1,8,-1,-1,-1" -same | \
  ssql to chart -x index -y value_convolved -output highpass.html
```

## Pattern Detection with Correlation

Cross-correlation finds where a pattern appears in a signal. Autocorrelation finds repeating patterns.

### Cross-Correlating Two Sensors

Cross-correlation finds the time delay or similarity between two signals. This is useful for:
- Finding time lag between sensors
- Detecting signal propagation delays
- Comparing similar signals for alignment

```bash
# Create two related sensor signals with a time delay
cat > two_sensors.py << 'EOF'
import math
import random
print("index,sensor1,sensor2")

# sensor2 is sensor1 delayed by 20 samples + noise
delay = 20
for i in range(500):
    # Base signal: sine wave with some variation
    base = math.sin(2 * math.pi * i / 50) + 0.5 * math.sin(2 * math.pi * i / 23)

    sensor1 = base + 0.2 * random.gauss(0, 1)

    # sensor2 sees the same signal, but delayed
    delayed_i = i - delay
    if delayed_i >= 0:
        delayed_base = math.sin(2 * math.pi * delayed_i / 50) + 0.5 * math.sin(2 * math.pi * delayed_i / 23)
        sensor2 = delayed_base + 0.2 * random.gauss(0, 1)
    else:
        sensor2 = 0.2 * random.gauss(0, 1)

    print(f"{i},{sensor1:.4f},{sensor2:.4f}")
EOF

python3 two_sensors.py > two_sensors.csv

# View both sensors
ssql from two_sensors.csv | \
  ssql limit 200 | \
  ssql to chart -x index -y sensor1 -output sensor1.html

ssql from two_sensors.csv | \
  ssql limit 200 | \
  ssql to chart -x index -y sensor2 -output sensor2.html

# Cross-correlate to find the delay
ssql from two_sensors.csv | \
  ssql correlate -field sensor1 -with sensor2 | \
  ssql to chart -x lag -y correlation -output cross_corr.html

echo "Peak in cross_corr.html shows the 20-sample delay"
```

**Finding the exact delay:**
```bash
# Find the lag with maximum correlation
ssql from two_sensors.csv | \
  ssql correlate -field sensor1 -with sensor2 | \
  ssql sort -desc correlation | \
  ssql limit 1 | \
  ssql to table
```

### Autocorrelation for Periodicity Detection

```bash
# Create a periodic signal
cat > periodic.py << 'EOF'
import math
import random
print("index,value")
for i in range(1000):
    # Period of 50 samples
    periodic = math.sin(2 * math.pi * i / 50) * 10
    noise = random.gauss(0, 2)
    print(f"{i},{periodic + noise:.2f}")
EOF

python3 periodic.py > periodic.csv

# View the signal
ssql from periodic.csv | \
  ssql to chart -x index -y value -output periodic.html

# Autocorrelation to find the period
ssql from periodic.csv | \
  ssql correlate -field value -auto -max-lag 200 | \
  ssql to chart -x lag -y correlation -output autocorr.html

echo "Peaks at lag=50, 100, 150... show period of 50 samples"
```

## Spectrogram Analysis (STFT)

While FFT shows frequency content of an entire signal, a **spectrogram** shows how frequencies change over time. This uses the Short-Time Fourier Transform (STFT) - applying FFT to overlapping windows.

### Basic Spectrogram

```bash
# Create a signal with changing frequency (chirp)
cat > chirp.py << 'EOF'
import math
print("index,amplitude")
sample_rate = 1000
duration = 2.0

for i in range(int(sample_rate * duration)):
    t = i / sample_rate
    # Frequency increases from 10 Hz to 100 Hz over 2 seconds
    freq = 10 + 45 * t  # Linear chirp
    amp = math.sin(2 * math.pi * freq * t)
    print(f"{i},{amp:.6f}")
EOF

python3 chirp.py > chirp.csv

# Compute spectrogram
ssql from chirp.csv | \
  ssql spectrogram -field amplitude -window-size 256 -rate 1000 | \
  ssql limit 20 | ssql to table
```

Output shows, for each window, its start `time` (and `time_index`), and
the magnitude at each frequency bin:
```
_line_number   frequency   magnitude            time   time_index
-----------------------------------------------------------------
           0           0   0.7994205041556737      0            0
           1     3.90625   1.3536425387430444      0            0
           2      7.8125    3.756500582337673      0            0
           3    11.71875   10.869330770522408      0            0    <- rising toward the 10 Hz start
           4      15.625    26.90292248197318      0            0
...
```

### Visualizing Frequency Changes Over Time

```bash
# Create spectrogram visualization
ssql from chirp.csv | \
  ssql spectrogram -field amplitude -window-size 256 -hop 64 -rate 1000 | \
  ssql where -if frequency le 150 | \
  ssql to chart -x time -y frequency -output spectrogram.html

echo "Open spectrogram.html - shows frequency rising from 10 to 100 Hz"
```

### Window Functions

Different window functions trade off frequency resolution vs. spectral leakage:

```bash
# Compare window types at the same window (time_index 8 ≈ 1.0 s with a 128-sample hop)
for window in hann hamming blackman none; do
  ssql from chirp.csv | \
    ssql spectrogram -field amplitude -window-size 512 -window-type $window -rate 1000 | \
    ssql where -if time_index eq 8 | \
    ssql sort -desc magnitude | \
    ssql limit 3 | \
    ssql update -set window $window
done | ssql to table
```

| Window | Best For |
|--------|----------|
| `hann` | General purpose (default) |
| `hamming` | Speech processing |
| `blackman` | High dynamic range |
| `none` | Maximum frequency resolution |

### Spectrogram Parameters

```bash
# High time resolution (small window, small hop)
ssql from chirp.csv | \
  ssql spectrogram -field amplitude -window-size 128 -hop 32 -rate 1000 | \
  ssql where -if frequency le 150 | \
  ssql to chart -x time -y frequency -output spec_time_res.html

# High frequency resolution (large window)
ssql from chirp.csv | \
  ssql spectrogram -field amplitude -window-size 1024 -hop 256 -rate 1000 | \
  ssql where -if frequency le 150 | \
  ssql to chart -x time -y frequency -output spec_freq_res.html

echo "Compare the two - tradeoff between time and frequency resolution"
```

```bash
# Magnitude (default) - linear scale

# Power - magnitude squared (energy)
```

### Detecting Frequency Transitions

```bash

import math
```

```bash
# Simulate machine vibration with bearing fault frequency

import math
import random
print("time,acceleration")
sample_rate = 10000

# Normal rotation: 25 Hz

```

### Example 3: ECG Signal Processing

```bash
# Simulate ECG-like signal
cat > ecg_sim.py << 'EOF'
import math
import random
print("time,voltage")

def qrs_complex(t, center):
    """Generate a QRS complex centered at 'center'"""
    dt = t - center
    if abs(dt) > 0.1:
        return 0
    # Simplified QRS shape
    return 1.5 * math.exp(-500 * dt * dt) - 0.3 * math.exp(-100 * (dt - 0.03) ** 2)

sample_rate = 500  # 500 Hz
duration = 5.0
heart_rate = 72  # BPM
beat_interval = 60.0 / heart_rate

for i in range(int(sample_rate * duration)):
    t = i / sample_rate
    voltage = 0
    # Add QRS complexes
    beat_num = 0
    while beat_num * beat_interval < duration:
        voltage += qrs_complex(t, beat_num * beat_interval + 0.1)
        beat_num += 1
    # Add noise
    voltage += 0.05 * random.gauss(0, 1)
    # Add baseline wander (low frequency)
    voltage += 0.1 * math.sin(2 * math.pi * 0.3 * t)
    print(f"{t:.4f},{voltage:.4f}")
EOF

python3 ecg_sim.py > ecg.csv

# View raw ECG
ssql from ecg.csv | \
  ssql where -if time le 3 | \
  ssql to chart -x time -y voltage -output ecg_raw.html

# Remove baseline wander with high-pass filter (FFT method)
ssql from ecg.csv | \
  ssql fft -field voltage -rate 500 -phase | \
  ssql where -if frequency ge 0.5 | \
  ssql ifft -magnitude magnitude -phase phase | \
  ssql update -set-expr time 'index / 500.0' | \
  ssql where -if time le 3 | \
  ssql to chart -x time -y signal -output ecg_filtered.html

# Find heart rate using autocorrelation
ssql from ecg.csv | \
  ssql correlate -field voltage -auto -max-lag 500 | \
  ssql to chart -x lag -y correlation -output ecg_autocorr.html

echo "Compare ecg_raw.html and ecg_filtered.html"
echo "Autocorrelation peak in ecg_autocorr.html shows beat interval"
```

**Applying audio effects and saving:**
```bash
# Read WAV, apply smoothing filter, save result
ssql from song.wav | \
  ssql convolve -field amplitude -kernel gaussian -size 11 -same | \
  ssql update -set-expr amplitude 'amplitude_convolved' | \
  ssql include sample amplitude | \
  ssql to wav -rate 44100 smoothed.wav
ls -l smoothed.wav

# Convert back to MP3 if needed:  ffmpeg -i smoothed.wav -b:a 192k smoothed.mp3
```

**Comparing two audio files:**
```bash
# Cross-correlate to find if one is a time-shifted version of another
ssql from song.wav > f1.jsonl
ssql from smoothed.wav > f2.jsonl

# Join on sample index and correlate
ssql from f1.jsonl | \
  ssql join f2.jsonl -using sample -as amplitude amplitude2 | \
  ssql correlate -field amplitude -with amplitude2 | \
  ssql sort -desc correlation | \
  ssql limit 5 | \
  ssql to table
```

## Performance Tips

### 1. Use GPU for Large Datasets

```bash
# codelab: skip — needs the ssql_gpu build
# CPU version - fine for small signals
ssql from small_signal.csv | ssql fft -field value

# GPU version - 28-54x faster for signals >= 16K samples
ssql_gpu from large_signal.csv | ssql_gpu fft -field value
```

### 2. Chain Operations Efficiently

```bash
# Good: Single pipeline
ssql from multi_freq.csv | \
  ssql fft -field amplitude -rate 1000 -phase | \
  ssql where -if frequency le 100 | \
  ssql ifft -magnitude magnitude -phase phase | \
  ssql limit 3 | ssql to table

# Avoid: Multiple separate invocations with intermediate files
ssql from multi_freq.csv | ssql fft -field amplitude -rate 1000 -phase > fft.jsonl
ssql from fft.jsonl | ssql where -if frequency le 100 > filtered.jsonl
ssql from filtered.jsonl | ssql ifft -magnitude magnitude -phase phase | ssql limit 3 | ssql to table
```

### 3. Use -max-lag for Autocorrelation

When searching for periodicity, limit the search range:

```bash
# Slow: Full autocorrelation (O(n^2) via FFT)
ssql from periodic.csv | ssql correlate -field value -auto | ssql count

# Fast: Limited lag (O(n * maxLag) direct computation)
ssql from periodic.csv | ssql correlate -field value -auto -max-lag 100 | ssql count
```

### 4. Filter Before FFT When Possible

```bash
# If you only need part of the signal, cut it first (a power-of-two length is fastest)
ssql from multi_freq.csv | \
  ssql limit 2048 | \
  ssql fft -field amplitude -rate 1000 | \
  ssql count
```

### 5. GPU Memory Considerations

**Memory estimation:** FFT requires approximately `signal_samples × 24 bytes` of GPU memory (input + complex output + workspace). For a 24GB GPU, this means ~1 billion samples max; for 8GB, ~330 million samples.

**If your signal exceeds GPU memory**, you have several options:

**Option A: Spectrogram (frequency content over time)**
```bash
# codelab: skip — illustrates chunking a file too big for GPU memory (huge.csv, ssql_gpu)
# Create spectrogram with 1M-sample windows, labeled by time offset
window=1000000
for offset in $(seq 0 $window 10000000); do
  ssql from huge.csv | \
    ssql offset $offset | \
    ssql limit $window | \
    ssql_gpu fft -field value -rate 1000 | \
    ssql update -set window_start $offset
done > spectrogram.jsonl

# Analyze: find peak frequency in each time window
cat spectrogram.jsonl | \
  ssql group-by window_start -max magnitude peak_magnitude
```

**Option B: Extract summary statistics per chunk**
```bash
# codelab: skip — illustrates chunking a file too big for GPU memory (huge.csv, ssql_gpu)
# Get dominant frequency from each chunk (no need to store full spectrum)
for offset in $(seq 0 1000000 10000000); do
  ssql from huge.csv | \
    ssql offset $offset | \
    ssql limit 1000000 | \
    ssql_gpu fft -field value -rate 1000 | \
    ssql sort magnitude -desc | \
    ssql limit 1 | \
    ssql update -set chunk_offset $offset
done > dominant_frequencies.jsonl
```

**Option C: Use CPU for very large single-shot FFT**
```bash
# codelab: skip — illustrative (huge.csv)
# CPU can use system RAM (slower but no VRAM limit)
ssql from huge.csv | ssql fft -field value -rate 1000
```

### 6. Compiling Generated Code with GPU Support

When you generate Go code from CLI pipelines, the code uses ssql library functions that automatically use GPU when available. To enable GPU acceleration in generated programs:

**Step 1: Install the GPU library (one-time setup)**
```bash
# codelab: skip — needs sudo and a CUDA build
# If you haven't already, install the CUDA library system-wide
cd /path/to/ssql
sudo make install-gpu  # Copies libssqlgpu.so to /usr/local/lib
```

**Step 2: Generate the code**
```bash
ssql generate go -pipeline 'ssql from multi_freq.csv | ssql fft -field amplitude -rate 1000' > fft_program.go
grep -c FFT fft_program.go
```

**Step 3: Build and run with GPU support**
```bash
# codelab: skip — needs a Go module with the gpu build tag and a CUDA library
# Build with gpu tag
go build -tags gpu -o fft_program fft_program.go

# Run normally (library is in system path)
./fft_program < input.csv
```

**Without `-tags gpu`:** Code still works but uses CPU only. This is useful for:
- Systems without NVIDIA GPU
- Small signals where CPU is fast enough
- Portability (no CUDA dependency)

**Automatic GPU selection:** The library automatically uses GPU when:
- Built with `-tags gpu`
- Signal >= 16K samples (FFT) or kernel >= 16 points (convolution)
- Smaller signals use CPU (faster due to no transfer overhead)

## Command Reference

| Command | Description | Key Flags |
|---------|-------------|-----------|
| `fft` | Time to frequency domain | `-field`, `-rate`, `-phase` |
| `ifft` | Frequency to time domain | `-magnitude`, `-phase`, `-output` |
| `convolve` | Apply filter kernel | `-field`, `-kernel`, `-custom`, `-size`, `-same`, `-output` |
| `correlate` | Cross/auto correlation | `-field`, `-with`, `-auto`, `-max-lag` |
| `spectrogram` | Frequency content over time (STFT) | `-field`, `-window-size`, `-hop`, `-window-type`, `-rate`, `-output` |

### Built-in Kernels for Convolution

| Kernel | Description | Example |
|--------|-------------|---------|
| `avg` | Simple smoothing (moving average) | `-kernel avg -size 21` |
| `gaussian` | Smooth Gaussian | `-kernel gaussian -size 21 -sigma 5` |
| `diff` | First derivative | `-kernel diff` |
| `laplacian` | Second derivative | `-kernel laplacian` |
| Custom | Your own values | `-custom "1,2,3,2,1"` |
