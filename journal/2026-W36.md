## 2026-09-03 (Thu) — `ssql fill` (DFC122 Tier 1, fourth unit)

Built straight on DFC124's definition of missing. `ssql.FillRecords`:
-down carries the last non-missing value forward (state = one map,
streams), -default gives a constant where still missing; down before
default so a leading gap takes the default. The command types -default
literals by the field's schema type (`-default score 0` on an int
column is int64 0), infers otherwise, and adds a -default field to the
schema when it was absent everywhere. Two-arg accumulate flag via the
rename `-as` Arg/Arg pattern. Declared OrderConsumes — the first Tier-1
verb where the parallel form would be semantically WRONG (shards don't
see each other's last value), not merely unavailable. Record-shaped by
design (typed structs can't hold missing — same reasoning as describe).
SQL: `SELECT * REPLACE (COALESCE(x, v) AS x, LAST_VALUE(y IGNORE NULLS)
OVER (ORDER BY <q.orderBy> ROWS UNBOUNDED PRECEDING) AS y)` — REPLACE
means no column list needed; -down without a preceding sort refuses
loudly (limit -last contract); a field both carried and defaulted nests
COALESCE(LAST_VALUE(...)). Gates: root golden (leading gap, carry,
real-0-untouched), SQL unit (found a nil-Op deref on the argv path —
the accessors tolerate nil, a direct field access didn't), completion
config, corpus (typed→record boundary), three equivalence pins on the
empties fixture incl. the duckdb oracle (unsorted -down: duckdb Skip
records the refusal). Sabotage (carry disabled) failed the unit AND the
duckdb lane. Tier 1 now has one unit left: extract + from lines. Ref:
DFC122, DFC124.

## 2026-09-03 (Thu) — `from … -last N`: the seek-based tail

Ross, testing v4.86: `from csv shuffled.csv | limit -last 10` reads the
whole 14.6M-row file. The mirror of DFC110's byte-offset sampling:
`tailLines` reads backwards from EOF in 64KB chunks until N+1 newlines
and replays header+lines through the ordinary CSV/TSV reader (one
parser, types inferred from the TAIL rows — pinned by a test where the
first data row is text and the tail is numeric); JSONL reads N+1 lines
so a `_schema` header landing in a tiny file's tail costs nothing.
Result: 0.01s vs 20.76s, identical rows. Wired as `-last` on the
csv/tsv/jsonl subcommands beside `-sample` (single file, no pushdown,
exclusive with -sample; URLs fall back to a full streaming read via
OpenHTTPStream + TakeLast). Codegen: one record-mode init fragment for
all modes (the -sample precedent). SQL: `read_csv(parallel=false)` +
row_number + reversed LIMIT + re-order — correct, not fast; refuses for
non-CSV/TSV. Optimiser: `limit-last-to-source` — needed a fix once the
CLI showed it silent: parseFromMultiFileCmd sets IsMultiFile only for
>1 file and single-file froms render from RawArgs, so the rule keys on
the parsed files and appends to both. Gates: root tail units (5000-row
file across chunk boundaries, CRLF, no trailing newline, header-only,
n>file), TestFromLastEqualsLimitLast (binary, csv+tsv, several N),
two equivalence cases incl. duckdb, SQL + optimiser units, and THE
gate — a scale-budget case (1s; measures 0.01s). Sabotage (off-by-one
in the tail) failed the duckdb lane, the equality test, and the unit.
Also recorded (Ross asked about -limit/-skip for symmetry): a flag
belongs on `from` only when the source can do what the stage cannot.
