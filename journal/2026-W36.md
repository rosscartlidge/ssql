## 2026-09-03 (Thu) — `ssql fill` (DFC122 Tier 1, fourth unit)

Built straight on DFC124's definition of missing. `ssql.FillRecords`:
-down carries the last non-missing value forward (state = one map,
streams), -default gives a constant where still missing; down before
default so a leading gap takes the default. The command types -default
literals by the field's schema type (`-default score 0` on an int
column is int64 0), infers otherwise, and adds a -default field to the
schema when it was absent everywhere. Two-arg accumulate flag via the
rename `-as` Arg/Arg pattern. Declared OrderConsumes — the first Tier-1
verb where the parallel form would be semantically WRONG (shards don't
see each other's last value), not merely unavailable. Record-shaped by
design (typed structs can't hold missing — same reasoning as describe).
SQL: `SELECT * REPLACE (COALESCE(x, v) AS x, LAST_VALUE(y IGNORE NULLS)
OVER (ORDER BY <q.orderBy> ROWS UNBOUNDED PRECEDING) AS y)` — REPLACE
means no column list needed; -down without a preceding sort refuses
loudly (limit -last contract); a field both carried and defaulted nests
COALESCE(LAST_VALUE(...)). Gates: root golden (leading gap, carry,
real-0-untouched), SQL unit (found a nil-Op deref on the argv path —
the accessors tolerate nil, a direct field access didn't), completion
config, corpus (typed→record boundary), three equivalence pins on the
empties fixture incl. the duckdb oracle (unsorted -down: duckdb Skip
records the refusal). Sabotage (carry disabled) failed the unit AND the
duckdb lane. Tier 1 now has one unit left: extract + from lines. Ref:
DFC122, DFC124.

## 2026-09-05 (Sat) — group-by -rollup/-cube: SQL translation, native typed form, 36 s → 1.7 s

**The semantics point that shaped both fixes.** ssql's rollup is NOT
SQL's ROLLUP (extra subtotal rows): it ENRICHES each detail group with
every grouping set's aggregates as prefixed columns (DFC048). So the
SQL is a detail GROUP BY joined to one subquery per grouping set
(`translateGroupByRollup`; NULL-safe `IS NOT DISTINCT FROM` keys;
`WITH __src` so the source is written once). One subquery per set,
aggregating the raw rows, is exact for AVG/MIN/MAX/LIST where a
window-function rewrite would only be right for COUNT/SUM. The sets and
the prefix rule are now exported (`ssql.RollupGroupingSets`,
`ssql.RollupFieldPrefix`) — one definition, every lane.

DuckDB 0.95 s · typed "cube" 36.7 s at 9.7 GB (the planner ejected

fallback, not typed. **Fix:** `typed.RollupEnrich` + `emitTypedRollup`
(typed_rollup.go): the detail group-by is the existing

aggregator's mergeable STATE; RollupEnrich then merges detail states

the record fallback with the reason under -explain.
