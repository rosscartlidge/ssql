## 2026-09-01 (Tue) — generate sql translates resample (DFC121 fully closed)

The last DFC121 slice: `translateResample` in
`cmd/ssql/commands/generate_sql.go` rebuilds the query around an
epoch-aligned `generate_series` grid and fills it with ASOF joins —
backward asof for previous, forward for next, both plus the
interpolation CASE for linear. Per-field `__sN` CTEs take
`max(value) GROUP BY ts` (the highest-wins duplicate rule) and skip
NULLs (raggedness matches the Go per-field series); edges clamp via

`-time-unit` pins it; an `error()` guard fires if `-every` is
finer than the unit. v1 refuses loudly on `-time-format` and
`-from`/`-to` (pointing at generate go), precedented by the
sample -seed refusal.

it on first run. Unit test TestTranslateResampleSQL mirrors the

## 2026-09-02 (Wed) — typed record-sink fix + `-pipeline` flag

Ross hit a v4.81.0 codegen bug within a day of release: `generate go
-mode typed` on a pipeline ending in `to chart` failed to compile
("too many return values" at the chart sink). Root cause: `to chart`
has no typed template, so the planner shims typed→Record and injects
the RECORD final fragment — whose `return fmt.Errorf(...)` is legal
under the record assembler (which rewrites it via fixErrorHandling)
but the typed assembler emitted finals VERBATIM into `func main()`
(no error return). Fix in `cmd/ssql/lib/codefragment_typed.go`: init
and final fragments now go through fixErrorHandling too, with "os"
imported on demand; fixErrorHandling itself now loops over every
occurrence instead of only the first. Coverage gap closed with
corpus case `record_sink_in_typed_pipeline_chart` (chart sink in all
three modes; sabotage-verified — reverting the fix fails typed with
Ross's exact error). Lesson: the corpus had no record-only-sink ×
typed-mode case, so a whole fragment CLASS (record finals in typed
main) was untested.

Same session, Ross's call: the `ssqlgen` shell helper isn't earning
its keep — replaced by `-pipeline '...'` on all three generate
commands. `runPipelineForFragments` factored out of the -script path
(same preprocessing: comments, leading-| continuations), `generate
go` honors -mode (default typed, exclusive with -script), sql/ssql
fix record mode. Six tests in `cmd/ssql/pipeline_flag_test.go`;
codelab §Shortcut rewritten from ssqlgen to -pipeline. Ross then
called the removal ("they are no help :-)"): -shell-helpers flag,
ShellIntegrations table row, ShellHelpersScript const, and its tests
are gone; -shell-init no longer emits ssqlgen; keybinding
integrations untouched. The TestShellIntegrationsCoverEmitters drift
guard stays consistent by construction (it globs emitter consts).
