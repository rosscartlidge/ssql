## 2026-11-23 (Mon) — FAQ: a review command for both logs (DFC169 §12.5)

Ross said the public FAQ "works really well" and asked for one command to review the questions and answers. Added `scripts/faq/review.sh`. It merges the LAN and public logs, with their `.1` generations, by time, and prints each question as a block: the question, the pipeline, any failure, then the reply, indented. It pages in `less` on a terminal. Filters: instance, `-since`, `-status`, `-grep`, `-n`, `-brief`. `-f` follows both logs.

Gotcha: a shell started before `install-public.sh` added you to the ssql-faq group doesn't have the group yet. The script falls back to `sg ssql-faq`, which works without a new login, and uses sudo only when you aren't a member at all. Tried live on both logs; follow mode was checked against a scratch log.

## 2026-11-23 (Mon) — FAQ: the brew and Go answers as eval cases; the jail's task cap (DFC169 §12.6)

Ross asked for the two bad public answers to become eval cases. The existing `doc-go-program` only checked that the reply mentioned "generate go", so it passed while the live answer was unverified. Doc cases can now name the `status` the page and log must show: the same words `review.sh` prints. `doc-install-any` wants `setup` and `doc-go-program` wants `verified`.

**Gotcha: the jail's 64-task cap.** Running the suite repeatedly made `TestAskGeneratedGo` flaky with "pthread_create failed". Every ssql stage is a Go process with a thread per core (24 here), so a four-stage pipeline could pass 64 tasks. The fix is `GOMAXPROCS=2` in the jail, with the cap raised to 256. `TestJailFitsALongPipeline` failed first. Deployed to the LAN instance.

**Two commands in one block.** `doc-go-program` passed when asked twice in a row but failed right after another question, presumably because of Ollama's prompt cache. The model gave two commands in one block, and `extractPipeline` joined them into one line, which no correction recovered from. `blockCommands` now splits a block at lines that don't continue the one before, and a block with more than one command gets a correction listing them. The Go case passes after one correction. `TestAskTwoCommandsInOneBlock` failed with the check switched off.

The full eval scored 37/40. `orders-per-month` depends on what was asked just before it, and passes alone at HEAD and with the change. `doc-latest-changes` was stale after v4.148.1 and was updated. **Lesson:** the eval's cases run in sequence, so a model's answer can depend on the case before it. A case that fails in the full run but passes alone isn't automatically a regression; compare against HEAD the same way.

All three are model-quality points for the next log review, not page bugs.
