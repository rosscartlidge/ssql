## 2026-09-29 (Mon) — DFC140: audit of every user doc, cleanup recommendations

Ross: "everything in `doc/*` (not research) should be correct and useful
to users; anything else should be either removed or moved somewhere
else." Nothing changed yet; the deliverable is
`doc/research/dfc140_user_doc_cleanup.md` for him to review.

**Method.** Four parallel read-throughs (CLI docs; api-reference /
EXPRESSIONS / library-tour; codelabs / typed / performance / install /
index; the ai-* family + VALIDATION + archive), each checking every
flag against `-help`, every signature against `go doc`, every claim
against CHANGELOG, plus who consumes each file (`scripts/*.sh`,
Makefile). I re-ran the load-bearing runtime claims by hand before
writing them down. 26 files, 15,170 lines.

**What it found.** No legacy `SSQLGO`/`ssqlgen`/`top -by`/`/v4`-less
patterns anywhere — the drift is subtler than the checklist assumed:

- The `_schema` header line has silently broken every jq recipe in
  `cli-debugging.md` and the older half of `cli-troubleshooting.md`
  (`head -1 | jq keys` → `["_schema"]`, all counts +1, `|= tonumber`
  errors on the header). Same root cause gives phantom rows in three
  `for … done | ssql to table` loops in `cli-signal-processing.md`; one
  of them is runner-executed and `make doc-test` passes because the
  oracle is a substring — the `top`-corpus lesson again.
- Flags that do not exist: `where -expr` (EXPRESSIONS, five places),
  `ssql group`, `correlate -field-a`, `to chart FILE`, `to json` as
  JSONL, `generate go -typed`.
- Advice that predates a feature: silent zero-row filters (now loud
  unknown-field errors), `split -l` for big files (now `-spill`; and it
  drops the CSV header), jq type fixes (now `cast`), "expr errors are
  logged and skipped" (they fail the pipeline), Tier 3 lists for things
  that transpile.
- api-reference: ~20 wrong signatures/structs (`TimeSeq` as a getter,
  seven nonexistent MutableRecord methods, `JoinPredicate` as a func,
  `CSVConfig`/`CommandConfig`/`ChartConfig`/`ExploreConfig` fields that
  don't exist), ~10 non-compiling examples, four duplicated sections,
  broken TOC. Check 11 lets it through because it matches a word, not a
  signature line.
- One benchmark, two values: 0.15 s (typed-reference) vs 0.32 s
  (performance.md) for the same 14.6 M group-by; 1.7 s vs 0.27 s for the
  cube. Three files carry copies of the same tables.
- Maintainer material leaking into user docs: DFC numbers in prose,
  version stamps written as news, "lanes"/"Tier 3"/"Phase B".
- The ai-* family: two of eight files are user-facing prompts (both
  need signature/flag fixes since an LLM copies them verbatim), one is
  a 648-line human guide with fictional success stories, five are
  maintainer or script-generated artifacts (one with a `/home/rossc`
  path committed).

**Verdicts.** 3 REMOVE, 4 MOVE to research/archive, 3 RESTRUCTURE
