# Journal — 2026-W26

## 2026-06-22 (Mon) — Exploration doc: interactive help at the cursor

Wrote a design/exploration doc (no code) for showing **help on the
command/flag/arg under the cursor** while editing the line — not just
completion candidates. The user's framing: this is general enough to belong
in **autocli**, with ssql as the first consumer, and the "super cool" angle
is using **tmux** subwindows for the display.

`doc/research/interactive-help-at-cursor.md`, indexed in
`doc/research/README.md`. Pushed to GitHub (commit `9855a91`, docs only).

The grounding insight that shapes the whole proposal: **help-at-point is the
existing completion context rendered as help.** autocli's
`analyzeCompletionContext(args, pos)` already locates the cursor (subcommand
path, current flag, `ArgIndex`, clause) for completion — so help is a *second
renderer* over the same analysis, not new machinery. Verified the help content
already lives in the tree (`FlagSpec.Description`/`ArgNames`/`ArgTypes`, command
`Description`, examples; `GenerateHelp*` render whole commands). There is no
existing `HelpAt`/`-help-at` — it'd be a small new primitive.

Proposed shape:
- **autocli core:** `Command.HelpAt(args, pos) (*HelpResult, error)` mirroring
  `Complete`, plus a `-help-at "<line>" <point>` protocol flag parallel to
  `-complete N`.
- **Triggers:** bash `bind -x` help key reading `READLINE_LINE` (the proven
  Ctrl-O / Ctrl-T pattern); autocli-shell `AutoCompleteCallback(line, pos, key)`
  branch — which sees every keystroke, enabling a live pane.
- **Display (the tmux angle):** inline print (floor) → `tmux display-popup`
  (transient context overlay, fzf-preview-style) → live `tmux split-window`
  help pane that tracks editing → optional in-shell overlay. Gated on `$TMUX`,
  degrades gracefully. Noted a "tutor mode" idea: the pane showing each stage's
  output schema via the existing `generate schema` path.

This is the third member of the `READLINE_LINE` / `(line,pos,key)` action
family — Ctrl-O (complete from upstream schema), Ctrl-T (optimise in place),
and now a help key (explain under the cursor). Confirmed tmux + `display-popup`
are available on this box, so the rich path is buildable.

### Next

Doc only — nothing implemented. If picked up: start with the autocli `HelpAt`
primitive + `-help-at` flag (pure renderer over existing context), then the
bash keybinding emitter and tmux display adapter. Open questions captured in
the doc §9 (key choice `Alt-h` vs `Shift-Tab`, granularity, live-pane
plumbing, popup-vs-pane default).

## 2026-06-22 (Mon) — Implemented help-at-cursor (autocli `HelpAt` + ssql Alt-h)

Built v1 of the exploration above. User decisions: **Alt-h**, **tmux popup
with inline fallback**, **autocli core + ssql bash binding** (defer the
in-process shell key and live panes).

**autocli** (`help_at.go`, new): `Command.HelpAt(args, pos) (string, error)`
mirrors `Complete` — walks the subcommand tree to the leaf the cursor sits in
(same logic as `completeWithSubcommands`), builds the synthetic `tempCmd`
(root globals + leaf flags), runs `analyzeCompletionContext`, then renders.
The key wrinkle: `analyzeCompletionContext` returns *early* for a flag-like
partial (cursor literally on `-sum`) without setting `FlagName`, so `flagHelpAt`
handles two cases — partial-is-a-flag-token (match by name) and cursor-on-an-
argument (`FlagName` set, mark `ArgIndex` with a `→`). Falls back to the
subcommand's full `GenerateHelp` when the cursor isn't on a flag. Wired
`-help-at` into `ExecuteWith`'s protocol switch next to `-complete`
(`parser.go`). 5 new tests, full autocli suite green.

**ssql** (`commands/help_keybinding.go`, new): `-help-keybinding` emits a
`bind -x` Alt-h binding. The function isolates the current pipeline stage
(text after the last `|` up to the cursor), splits it with `read -ra` (no
glob), computes the COMP_WORDS-style `pos` (trailing-space → new empty word),
and calls `command ssql -help-at "$pos" "${words[@]:1}"`. Display adapter
`_ssql_show_help`: `tmux display-popup` when `$TMUX`, else inline `printf`.
Intercepted in `main.go` before autocli (like the other two keybindings;
`-help-at` itself is *not* intercepted — it flows to autocli). Added to the
bare-`ssql` integration list.

**Gotcha that the pty test was built to catch but didn't bite:** Alt-h is
ESC-prefixed, and in vi mode ESC also leaves insert mode — I expected vi to
need a different key. `TestHelpKeybindingPTY` (real pty, emacs+vi, keyseq-
timeout 1) **passed both modes first try**: with the chord written as one
`os.write(b"\x1bh")` and timeout 1ms, readline matches the `\eh` binding
before treating ESC as a mode switch. Same split-on-`\r` capture discipline as
the other pty tests. One unit-test harness nit: `_ssql_help_at`'s guard
`return` propagated exit 1 to the `bash -c` script and made `Output()` error —
appended `true` after the call (the optimise test dodged this by printing
`READLINE_LINE` after the call).

**Cross-module coordination (the one loose end):** ssql depends on the
*published* autocli `v4.8.0` — no `replace`. The new primitive lives in local
autocli, so I added a temporary `replace … => /home/rossc/src/autocli` to
`ssql/go.mod` to build and test. This must NOT be committed (CLAUDE.md bans
`replace` in releases). To ship: tag an autocli release carrying `HelpAt`/
`-help-at`, bump ssql's `require`, drop the `replace`. Held off on the autocli
tag + the ssql commit/push until asked. Smoke-tested against the real tree —
`ssql -help-at 5 group-by dept -sum salary total` correctly marks `→ result-
name`. CHANGELOG under `[Unreleased]`; codelab has an "Help at the Cursor
(Alt-h)" section; TODO #97 ticked.

**v4.49.1** — a cluster of small things that came out of the user actually
*using* Alt-h, plus a real bug:

- **`generate ssql` parquet column-pruning bug.** `collectDownstreamFields`
  unioned field refs from every downstream command, so a `group-by` *output*
  name (e.g. `-count count`) leaked back as a phantom source column →
  `from parquet … -columns count`, a column the file doesn't have. The CLI

  but the **`generate go`** path passed the list straight to the parquet reader
  → invalid projection. That's the failure the user hit. Fix: `group-by` is a
  schema barrier — stop the downstream scan there (new `redefinesSourceSchema`).
  Regression test `TestCollectDownstreamFields_GroupByBarrier`. The lesson worth
  remembering: the CLI's tolerance masked a bug that only bit the typed/Go path.

- **Alt-r (`-run-keybinding`)** — "convert to typed and run". Reuses the
  existing `generate go -run` (typed Go → `go build -mod=mod` in a temp dir →
  exec; go.mod pins `version.Version`, so the build resolves the cached
  release). Streams output inline, line preserved. NOT instant and DOES read
  data — the only member of the family that compiles and runs. Real-pty test
  asserts on the compile *notice* (not compiled output) so it doesn't hinge on
  toolchain/module resolution in the pty.

- **Alt-H** cheat-sheet of the whole family (Ctrl-O, Ctrl-T, Alt-r, Alt-h,
  Alt-H), reusing `_ssql_show_help`. Chose Alt-H over Alt-? (which would clobber
  readline's default `possible-completions`).

- **Help-popup polish** (all from live use): `less` now reads via stdin
  redirect → bare `:` prompt instead of the `/tmp/tmp.XXXX` path; popup clamped
  to `client_width/height` so it stops erroring "width/height too large" in
  small windows. (A fits-the-screen branch that skipped the pager via `read`
  was tried and reverted — `display-popup -E` gives the command no interactive
  stdin, so `read` returned instantly and the popup flashed shut.)

The `READLINE_LINE` action family is now five keys: Ctrl-O complete, Ctrl-T
optimise, Alt-r run-typed, Alt-h help-at-cursor, Alt-H key list. Bare `ssql`
advertises all of them.

**Deployments** (both public, done after release): gh-pages playground rebuilt

## 2026-06-23 (Tue) — v4.50.0: honest field-name completion (Tab→Ctrl-O), Alt-g; autocli v4.10.0

The big one. Driven by the user's observation that Tab field completion "still
uses the old environment method - so is often wrong."

**The diagnosis.** Tab field-NAME completion was fed by `AUTOCLI_FIELDS` — an
env cache that `from <file>` populated by snapshotting the file header, then
downstream `where -if`/`group-by`/`sort` read. It went **stale** the moment the
pipeline renamed/aggregated/joined → confidently completed the WRONG names.
Worse than the CLI: those wrong names flowed into `generate go`/`generate ssql`.
The reason it can't be fixed in place: bash `complete -F` scopes
`COMP_LINE`/`COMP_WORDS` to the command after the last pipe, so a completion
function literally can't see upstream (proven earlier). Only a `bind -x` key
(READLINE_LINE) can — which is why Ctrl-O exists.

**Surgical removal (autocli v4.10.0).** Deleted the field-NAME cache:
`getCachedFields`/`sanitizeForEnv`, `CompletionDirective.Fields`, and all the
`AUTOCLI_FIELDS` bash plumbing including the procsub "outer fields" path.
**Kept** `AUTOCLI_CACHE_FILE` (the source file *path*) — value completion uses a
*different* cache and was never stale (it samples the real file, degrades to a
`<VALUE>` hint when the field isn't there). So `-if dept eq <TAB>` still works.
Key realization while mapping it: one `field_cache` directive fed *both* env
vars, so "delete everything" would've killed value completion too — it had to
be surgical (drop `.fields`, keep `.filepath`). On the ssql side, removed the
now-pointless SSH header round-trip and the catalog metadata-column directive
(both only fed the dead name cache).

**The magnitude:** because every ssql stage is its own process, this makes
*essentially all* pipeline field-NAME Tab completion return a hint — Ctrl-O is
now THE way to complete field names. The user accepted that ("honest is best").

**The lovely part — Tab→Ctrl-O hand-off (the user's idea).** Instead of a dead
`<FIELD>` (which `printf %q` even mangled to `\<FIELD\>`), autocli got a
`FieldNameHint` var; ssql sets it to **`Use-Ctrl-O`**. So Tab inserts a
self-documenting placeholder; pressing **Ctrl-O** detects that exact token,
deletes it, and completes from the live schema. Gotcha caught by the pty test:
bash appends a trailing space after the unique completion, so the Ctrl-O
function must strip `Use-Ctrl-O` *with or without* that space. `FieldHintToken`
is the single source (wired into `cf.FieldNameHint` via `init()`, matched in the
bash function; `TestFieldHintTokenConsistent` enforces it's shell-safe and
consistent). Full flow pty-tested in emacs + vi (`TestFieldTabHandoffPTY`).

**Also shipped (v4.50.0):** `Alt-g` (`ssql -code-keybinding`) — show the typed
Go the pipeline generates, no run; and the `KeyBindings` single-source-of-truth
table that generates the Alt-H cheat-sheet, with `TestKeyBindingsInSync`
scanning every emitter script so a new binding can't drift from the help.

Released autocli v4.10.0 (tag/push/proxy-verify) then ssql v4.50.0 (full flow;
proxy verify 404'd on the fresh tag until `sum.golang.org` indexed it —
`GOSUMDB=off` confirmed the module, standard transient). Both deployments live:
gh-pages playground rebuilt, WebVM Deploy completed success.

## 2026-06-23 (Tue) — v4.50.1: typed-codegen projection var collision fix

User hit it via Alt-r: `ssql from csv … | ssql include relationship a_name |
ssql rename -as relationship rrr | ssql group-by rrr` failed to compile in
typed mode. Two layers:

1. **A sum.golang.org 404** on the fresh v4.50.0 tag — my fault: when the
   release proxy-verify 404'd I confirmed with `GOSUMDB=off`, which never warms
   proxy.golang.org/sum.golang.org. So the public sum DB had no record and the
   user's `go build` (via generate go -run) refused it. Fix for the user:
   `export GOPRIVATE=github.com/rosscartlidge/*` (fetches own modules direct
   from GitHub — also makes future fresh releases work instantly). **Lesson:
   verify releases through the DEFAULT proxy (not GOSUMDB=off) so the sum DB
   actually gets warmed.** Did exactly that for v4.50.1 — warmed on try 1.

2. **A real, pre-existing typed-codegen bug** the 404 was masking. The typed
   assembler names projection outputs from a tiny fixed set — `include`→
   "included", `rename`→"renamed", `exclude`→"excluded" — and a no-aggregation
   `group-by` projects to its keys like an include, also "included". So
   `include … | group-by FIELD` (or two includes) emitted two `included :=` →
   "no new variables on left side of :=" + Stream type mismatch. Record mode
   and interpreted execution were fine; only typed codegen (what Alt-r uses)
   broke.

**Fix:** `uniqueVarName(base, fragments)` in `typed_projection.go` — each
codegen process already receives the full upstream fragment stream on stdin, so
checking output names against it gives globally unique names with no
cross-process coordination (`included` → `included2` → …). `emitTypedProjection`
returns the chosen name; group-by threads it into its `typed.Distinct` and also
uniquifies its own "grouped". Covers two-includes, exclude→group-by, two no-agg
group-bys, rename→include. Regression: corpus case `include_then_groupby`
(record + typed + parallel) — full corpus green.

Released v4.50.1 (patch, ssql-only — no autocli change): tag, proxy-warm-verify
(try 1), debs, install-local (both binaries), playground, doc-check 36/36,
gh-pages + WebVM deploys (both success).

## 2026-06-24 (Wed) — Design doc: codegen fragment-IR evolution (why not go/ast)

Discussion, not code. The v4.50.1 variable-collision bug reopened a long-running
question: should the code generator assemble an AST instead of strings?

Wrote `doc/research/codegen-ir-evolution.md` arguing **no — keep the current
system**, with reasons grounded in the actual architecture:

- The codegen is a **distributed fragment IR with a planner**, not naive string
  concat. Each `ssql` stage is its own process emitting `CodeFragment` JSON down
  a pipe; the planner does reach analysis over `Capabilities` and swaps
  parallel/serial forms. Good bones.
- `go/ast` is the wrong fix for two architectural reasons: (1) the per-process
  pipe model needs a *serializable* node — go/ast doesn't serialize cleanly;
  (2) three backends (go/sql/ssql) want a *language-neutral relational* IR, and
  go/ast is Go-only and built for parsing, not synthesis. Readable output (a
  hard CLAUDE.md goal) also wants templates, which go/format would flatten.
- The two real soft spots are incremental, not a rewrite: **(§4a)** a structured
  `Op` on `CodeFragment` so `generate sql`/`generate ssql` stop re-parsing the
  `Command` string (`parsePipelineCmd` is the IR the optimiser wishes it had),
  and **(§4b)** centralized variable binding at the assembler so v4.50.1-style
  collisions are structurally impossible (retires the per-process `uniqueVarName`
  heuristic). §4b is the small, self-contained piece to reach for first if
  another collision-class bug appears.

Then added **§7** after a good follow-up question: a language-neutral `Op`
makes "one IR, N backends" real — *already proven* (ssql lowers to Go, DuckDB
SQL, and ssql; SQL is a more alien target than Rust would be). The honest
caveat: the IR makes translation tractable but doesn't give you the *runtime*.
Generated Go calls into the `typed`/`ssql` library; SQL is the exception because
DuckDB *is* the runtime. So a Rust target should lower to an existing engine —
**DataFusion** (whose own logical plan is a relational IR: ssql Op → DataFusion
LogicalPlan → their runtime) or **Polars** — not hand-port the primitives. And
record-mode generation ports more easily than typed structs.

**Decision:** stay with the current system for now; the doc is the considered
option if the pain returns. Both commits pushed; indexed in
`doc/research/README.md`.

## 2026-06-24 (Wed) — v4.51.0: process-substitution-aware completion + join right-field

Surfaced by a good worry: how do the new Ctrl-O/Alt-h bindings interact with the
process-substitution paradigm (`ssql join <(ssql from kind.csv) -on a_kind kind
-as kind_name a_kind_name`)? Investigation found a real gap: the bindings split
the line on the last `|` with `${line%|*}` / `${line##*|}`, which is **not**
paren-aware — a `|` inside `<(ssql … | ssql …)` was mistaken for a top-level
pipe → malformed upstream → silent no-op. Also, join's *right*-side fields were
never completable (NoCompleter hint), since the right schema is the procsub.

**Fix:** moved the parsing into Go (testable, robust) behind two protocol flags,
keeping bash thin — `cmd/ssql/cursor_context.go`:
- `ssql -complete-source "<line>"` → the command whose `SSQL_MODE=schema` output
  feeds the cursor. Handles, in order: (1) cursor inside a `<(…)>` → that
  procsub's internal upstream; (2) a join right-side slot (`-on` 2nd arg / `-as`
  1st arg, clause-separator-aware) → the join's `<(…)>` source; (3) else the
  upstream pipeline. `joinRightFieldSlot` tracks flag + positional index across
  `+`/`-` separators.
- `ssql -cursor-stage "<line>"` → the current stage (paren-aware) for Alt-h.

Why Go not bash: paren-depth scanning in pure bash parameter expansion is
fragile and only pty-testable; in Go it's 17 string-in/string-out unit cases
(`cursor_context_test.go`) covering inner-pipe, inside-procsub, `-on`/`-as`
slots, separators, nesting. Plus a real-pty `TestFieldProcsubPTY` (Ctrl-O
right-field-from-procsub, emacs + vi). Existing keybinding/completion suite still
green through the new path.

User confirmed live: Ctrl-O on **every** field of a multi-lookup join — left
keys from upstream, right keys + `-as` source fields from the procsub, across
the `-` separator — exactly the shape in `ssql join -help`. Better than before
the worry: right-side fields were never completable at all previously.

ssql-only release (no autocli change — `FieldNameHint` already in v4.10.0).
Docs: `completion-system.md` gained a "Ctrl-O & process substitution" section;
fixed two now-stale limitations there. Released v4.51.0 — full flow + deploys.

## 2026-06-27 (Sat) — v4.51.1: keybinding error popups + `ssql -shell-init`

Polishing pass on the keybinding family.

**Errors in a subwindow.** Alt-g/Alt-r/Alt-h previously `2>/dev/null`'d their
errors and silently returned (or, for Alt-r, scrolled an inline error wall).
Now failures show in the popup (`_ssql_show_help`, popup-in-tmux / inline
otherwise):
- Alt-g: capture the failing STAGE's stderr (the clean message) and generate-go's
  stderr into separate temp files, prefer the stage error. The pipe means a
  stage's stderr can't be mixed into the fragment stream, hence temp files.
- Alt-r: split streams — the program's stdout STREAMS inline (the result, often
  large), its stderr → temp file; on non-zero `${PIPESTATUS[1]}` show the error
  in a popup. So success streams, failure pops.
- Gotcha the user caught: a pipeline can have MULTIPLE real errors (their case:
  `update -set-expr` AND `join`), each re-reported by downstream stages. A
  first-line trim would hide the second. New shared `_ssql_clean_err` (in
  `ssqlPopupFunc`) drops the re-report lines ("reading code fragments: code
  generation failed", "no code fragments received") and keeps the distinct real
  errors. Embedded `ssqlPopupFunc` into the run binding so it has the display +
  cleaner too.

**`ssql -shell-init`** — the requested single option. `eval "$(ssql
-shell-init)"` emits the completion script + every keybinding + `-shell-helpers`
in one go. Built on a single source-of-truth `ShellIntegrations` table
(`commands/shell_integration.go`) that now drives three things: `-shell-init`
concatenation, the bare-`ssql` hint (recommends `-shell-init` first, then lists
the pieces), and main.go's intercept (replaced the hardcoded if-ladder). Drift
guard `TestShellIntegrationsCoverEmitters` scans for `*KeybindingScript`/
`*HelpersScript` emitters and fails if one isn't in the table — proven to bite.
`TestShellInitIncludesAll` asserts -shell-init embeds every table script
verbatim + the completion script.

ssql-only release (no autocli change). Full flow + deploys.

## 2026-06-27 (Sat) — v4.51.2: Alt-h shows expression-function reference

User's insight: writing expressions is hard without knowing the functions, and
Alt-h is already "help at the cursor" — so when on an expression, Alt-h should
surface the function list. Even better, `ssql functions` already exists (49
lines, popup-perfect), so we surface what's there rather than build new.

- `exprArgAtCursor(args, pos)` (cursor_context.go) — detects when the cursor is
  on an EXPRESSION arg specifically, per command: where -if-expr/-x;
  update -if-expr/-x and -set-expr/-e (the EXPR, arg 1, not the field arg 0);
  group-by -expr/-e (arg 0, not result-name) and -stream-expr (args 0-2, not
  the result-name). Clause separators (+/-) reset. 16 unit cases.
- `FunctionsReference` const (functions.go) — extracted the category listing
  as a single source of truth; `printAllCategories` now prints it, and the help
  path appends it. `ssql functions` output byte-identical.
- ssql now intercepts `-help-at` (was flowing straight to autocli) to call
  autocli's HelpAt for the base flag help, then append FunctionsReference when
  exprArgAtCursor is true. Non-expression positions get no functions.
- Bonus: the bash _ssql_help_at now passes the empty cursor word on a trailing
  space, so autocli's `→` arg marker points at the expression rather than
  mis-marking the field (an off-by-one for the cursor-beyond-args case).

ssql-only release. Documented in cli-codelab.md (Alt-h section). Natural
on-ramp to the expr→Go transpiler work (the still-open big lever) — authoring
expressions is now much friendlier. Full flow + deploys.
