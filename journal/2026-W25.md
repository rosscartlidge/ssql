## 2026-06-15 (Monday) — v4.45.0 post-release checklist

Closed out the v4.45.0 release that shipped 2026-05-20 (Position 2
pipes in `ssql serve`). The release tag and binaries went out at the
time, but the post-release checklist had never been run — so this was
catch-up.

### What was stale

- **`ssql_gpu` had drifted to v4.44.6** while `ssql` was v4.45.0 —
  exactly the trap CLAUDE.md warns about (gpu drifted v4.32→v4.44
  unnoticed once before). `make install-local` refreshed both binaries
  in `$GOPATH/bin`; both now report v4.45.0 (gpu: no / gpu: yes).
- **CHANGELOG had no v4.45.0 entry** — top was v4.44.6. Backfilled it
  with the Position 2 pipes feature + the five serve fixes (to-table
  stdout, `ErrClosedPipe` suppression, Ctrl-C line-cancel,
  bare-transform stdin, pipe-aware completion). Dated to the actual
  ship date 2026-05-20.
- **WebVM binary was v4.44.2** — cross-compiled the v4.45.0 slim
  linux/386 build.

### Steps run

- `make deb` — rebuilt `ssql_4.45.0_amd64.deb` + `ssql-gpu_4.45.0_amd64.deb`
  (CUDA 12.8 local), committed the swap, removed the old v4.44.2 debs.
- `make install-local` — fixed the gpu drift (see above).
- `make playground` — rebuilt the 14M slim WASM.
- `make doc-check` — 36/36 pass. TODO.md already current (Position 2
  marked done in entry 90; schema-aware-completion design doc linked).
- Deployed gh-pages playground via the /tmp dance. Only
  `ssql-playground.wasm` actually changed — playground.html and
  wasm_exec.js were byte-identical to what's deployed. Notable: the
  gh-pages working tree has untracked cruft (`typed.test`, `typed/`,
  `dist/`, `dashboard.html`) that pre-dates this session; deliberately
  used `git add <files>` not `git add -A` to avoid sweeping it in. The
  documented deploy recipe says `git add -A` — that's a footgun on this
  tree and worth tightening later.
- Deployed WebVM: cross-compiled, pushed to `ssql-terminal`, triggered
  the Deploy workflow (run 27531560817) — completed/success in ~21s for
