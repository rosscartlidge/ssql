### gh-pages `git add -A` footgun — fixed

Root cause: `gh-pages` shares one working tree with `main`. `git
checkout gh-pages` removes main's *tracked* files but leaves main's
*ignored* artifacts (`typed.test`, `typed/typed.test`, `dist/`, a
generated `dashboard.html` — ~91MB) as untracked, because gh-pages had
**no `.gitignore` of its own**. The documented `git add -A` deploy
would have swept them into the branch.

Fix (gh-pages `28c68cc`): removed the stray artifacts, then added a
gh-pages `.gitignore` mirroring main's patterns. `git add -A` is now
safe — `git status` on gh-pages is clean, and tracked deploy assets
still stage normally (ignore rules never apply to tracked files;
verified by staging a real `playground.html` content change under the
`/*.html` rule). Documented the gotcha in `claude/playground.md`.

### `SSQLGO=schema` de-risk spike — done, doc corrected

Ran the two-front spike (two parallel agents, one per repo) before
committing to implementation. Both load-bearing assumptions had real
cracks; architecture survives but the doc was wrong in
implementation-breaking ways. Findings folded into a new §0 of
`doc/research/schema-aware-completion.md` (authoritative; the stale
inline sketches now carry ⚠ pointers to it).

**Separability (§4.3): HOLDS with caveats.** Every schema-mutating
command builds an explicit `*lib.Schema` before/independent of
iteration (pivot is the sole data-dependent case, correctly
`ok=false`). Big de-risk: `Command.Parse(args)` is reusable, so
SchemaOps don't hand-parse argv. But "5–15 lines" is optimistic for
**group-by** (4 sub-shapes + rollup/cube) and **join** (~20–40 lines;
*not* pure — does I/O on the right file's `_schema`, bails on process
substitution). Doc errors caught: `rename` is `-as old new` not
positional; `window` has no `-into` (17 result flags + real type
inference); `cast` emits no runtime schema so it can't be
shadow-tested. Pre-req: factor group-by's ~140-line ×2 agg-flag parse
into a shared `parseAggSpecs(ctx)` first.

**autocli surface (§7): sound strategy, every API name fictional.**
`Completer` is a clean one-method interface and `UpstreamFieldsCompleter`
+ `ChainCompleter` fallback drop in cleanly — but `CompleteWithContext`,
`ctx.UpstreamFields`, `ctx.State` all don't exist; real entry is
`Command.Complete(args, pos)` with no injectable context; completion
has no `State` analog; `tabComplete` currently discards everything
before the last `|`. Two misses: **layering** (shell is ssql-agnostic,
can't resolve ssql SchemaOps — needs a generic `SchemaWalk` callback
hook, ssql supplies the walker) and **release order** (needs autocli
**core** v4.7.0 first → shell v0.4.0 → ssql; not "shell-only").

**Decisions taken:** env var = **`SSQL_MODE=schema`** (umbrella; SSQLGO
becomes a deprecated alias, existing modes migrate to SSQL_MODE=*);
scope = **bundle Phase 1+2** (serve + bash, ≈5–6 days, SchemaOps shared
so marginal bash cost is just the plumbing).

### Slice 1: SSQLGO → SSQL_MODE env-var migration — done
