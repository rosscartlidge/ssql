# Week 8, 2026

## 2026-02-17 (Monday)

### WASM Module Redesign: TinyGo + Decoupled Architecture — v4.17.0

Rewrote `cmd/ssql-wasm` to be fully self-contained with zero dependency on `ssql/v4`. The old module imported the full ssql library (Arrow, Excel, expr-lang, etc.) just for 6 simple operations, producing a 15MB WASM binary. The new module has its own JSON parser, dataset types, and operations.

**Binary size results:**

| Build | Size |
|-------|------|
| Old (ssql/v4 dependency) | 15MB |
| Standard Go (decoupled) | 2.6MB |
| TinyGo | 245KB |

**New files:**
- `cmd/ssql-wasm/dataset.go` — Core types: `schema`, `record`, `dataset`, `rawJSON`
- `cmd/ssql-wasm/json.go` — Manual recursive-descent JSON parser & serializer (no `encoding/json`)
- `cmd/ssql-wasm/compare.go` — Comparison operators ported from old operators.go
- `cmd/ssql-wasm/main_stub.go` — Empty `main()` for non-WASM `go test` / `go build`
- `cmd/ssql-wasm/json_test.go` — 23 parser/serializer tests
- `cmd/ssql-wasm/operators_test.go` — 21 operation tests

**Rewritten files:**
- `cmd/ssql-wasm/operators.go` — Self-contained dataset methods (was ssql.Where/SortBy/etc wrappers)
- `cmd/ssql-wasm/main.go` — Uses `parseJSONArray`/`toJSON` instead of ssql bridge

**Deleted files:**
- `cmd/ssql-wasm/bridge.go` — Replaced by json.go

**Modified files:**
- `Makefile` — `wasm` target now uses TinyGo; added `wasm-go` fallback for standard Go

**Bug fixed:** Old `bridge.go` fed `JSON.stringify` output (a JSON array `[{...},{...}]`) to `ReadJSONFastFromReader` which is a JSONL parser expecting one object per line. This likely returned empty results, with the explorer silently falling back to JS aggregation.

**Design decisions:**
- No `encoding/json` — enables TinyGo which doesn't support reflection-based JSON
- `regex` operator falls back to `contains` in TinyGo (no `regexp` support)
- `sort.SliceStable` used instead of `slices.SortedFunc` (TinyGo compatible)
- JSON parser follows same recursive-descent patterns as `core.go:ParseJSONLine`
- Schema expansion handles objects with different fields (not just first-object schema)
