### WASM Module Redesign: TinyGo + Decoupled Architecture — v4.17.0

Rewrote `cmd/ssql-wasm` to be fully self-contained with zero dependency on `ssql/v4`. The old module imported the full ssql library (Arrow, Excel, expr-lang, etc.) just for 6 simple operations, producing a 15MB WASM binary. The new module has its own JSON parser, dataset types, and operations.

**Rewritten files:**

- `cmd/ssql-wasm/main.go` — Uses `parseJSONArray`/`toJSON` instead of ssql bridge

**Deleted files:**
- `cmd/ssql-wasm/bridge.go` — Replaced by json.go

**Modified files:**
- `Makefile` — `wasm` target now uses TinyGo; added `wasm-go` fallback for standard Go

**Bug fixed:** Old `bridge.go` fed `JSON.stringify` output (a JSON array `[{...},{...}]`) to `ReadJSONFastFromReader` which is a JSONL parser expecting one object per line. This likely returned empty results, with the explorer silently falling back to JS aggregation.

**Design decisions:**
- No `encoding/json` — enables TinyGo which doesn't support reflection-based JSON
- `regex` operator falls back to `contains` in TinyGo (no `regexp` support)
- `sort.SliceStable` used instead of `slices.SortedFunc` (TinyGo compatible)
- JSON parser follows same recursive-descent patterns as `core.go:ParseJSONLine`
- Schema expansion handles objects with different fields (not just first-object schema)

### Advanced WASM Processing: Pipeline Builder + New Operations

Transformed the explorer from a view-only tool with a single-step aggregation panel into an interactive data workbench. The existing WASM module had 6 operations but only `groupBy` was exposed in the UI. Now all operations are accessible through a pipeline builder, plus 4 new operations.

**Phase 1 — Pipeline Builder UI** (chart.go):
- Replaced the single "Aggregation" panel (group-by + apply/reset) with a general "Pipeline" panel
- Users add steps via a dropdown: Where, Sort, Group By, Multi-Group, Distinct, Limit, Computed Column, Pivot
- Each step type renders type-specific config fields (field dropdowns, operator selects, text inputs)
- "Run Pipeline" sends all steps to `ssqlWasm.pipeline()` as a single WASM call
- Result badge shows row count: "5 rows → 3 rows"
- JS fallback still works for single group-by without WASM

**Phase 2 — Multi-Group + Multiple Aggregations** (operators.go, json.go):
- New `groupByMulti(groupFields, aggs)` method groups by composite key (multiple fields)
- Each `aggSpec` has field, func, and alias — multiple aggregations per group
- UI allows adding/removing group fields and aggregation rows dynamically
- Example: group by dept+region with sum(salary), avg(salary), count

**Phase 3 — Computed Columns** (new: expr.go):
- Minimal recursive-descent arithmetic expression evaluator (~210 lines)
- Supports: field references, numeric literals, +, -, *, /, parentheses, unary negation
- Standard operator precedence (* / before + -)
- TinyGo-compatible (no reflection, no regexp)
- New `compute(name, expr)` method adds derived fields to dataset
- Example: `salary * 12` creates an `annual_salary` column

**Phase 4 — Pivot Tables** (operators.go):
- New `pivot(rowField, colField, valField, aggFunc)` method
- Unique values of `colField` become columns in the output
- Groups by `rowField`, applies `aggFunc` to `valField` for each cell
- Missing cells filled with 0 (int64 for count, float64 for others)
- Example: pivot dept × quarter with sum(revenue) → cross-tab

**Phase 5 — WASM-backed AG-Grid** (chart.go):
- AG-Grid `onFilterChanged`/`onSortChanged` events intercepted when WASM is available
- Filter model converted to WASM `where` ops (equals→eq, greaterThan→gt, etc.)
- Sort model converted to WASM `sort` ops
- Grid ops prepended to user's pipeline steps and executed as single WASM call
- `suppressGridEvents` ref prevents re-entrant updates
