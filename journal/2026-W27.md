**`ssql conventions`** (commands/conventions.go) — the third leg alongside

## 2026-06-30 (Tue) — v4.53.0: heap top-k in typed mode + generate-go -mode completer

Two user-reported quality issues, bundled.

**1. Typed `top` was a full sort.** `generate go -mode typed` on `… | top 10 -field z`
emitted `typed.SortByDesc + typed.Limit` (O(N·log N), O(N) mem) — the root
package has had `ssql.TopBy` (bounded heap, O(N·log K)/O(K)) all along, but the
`typed` package had no equivalent, so the codegen desugared to sort+limit and
marked the fragment `SerialOnly`. Fixed:
- New `typed/topk.go`: `TopBy`/`BottomBy` (serial, mirror root) + `TopByParallel`/
  `BottomByParallel` (per-shard size-n heap over a `Stream[T]`, merge the ≤shards·n
  survivors through one final size-n select — top-k is an associative reduction).
- Rewired `top.go` typed codegen to **dual templates**: parallel `Code`
  (`typed.TopByParallel`, Accepts ShapeStream / Produces ShapeSeqTyped) +
  `AltCodeIfSeq` (`typed.TopBy`, Seq→Seq). Dropped `SerialOnly`, so `from | top`
  stays fully parallel instead of forcing an upstream `Stream.Serial()`.
- Verified end-to-end: parallel form, `-asc` (BottomByParallel), and the
  serial-forced form (sort upstream → planner swaps to `typed.TopBy`) all compile
  and return correctly-ordered results.

**2. `generate go -mode <tab>` completed nothing** — the `-mode` flag had no
`Completer` at all. Added `StaticCompleter{record, typed}` (parallel omitted as
the deprecated alias) + tidied the help text.

Tests: `typed/topk_test.go` (serial correctness incl. string keys + edge cases;
`TopByParallel` vs serial multiset gate; **-race** clean per the concurrency
rule); updated `TestTypedTopBy` (now asserts `TopByParallel`, not sort+limit) +
new `TestTypedTopBySerialForm`; `mode_completion_test.go` drives the real
`-complete` path; corpus `top` + new `top_asc` cases pass across record/typed/
parallel; **full corpus green (43s)**, `cmd/ssql -short` green (255s). gofmt only
flags the pre-existing `RegisterTop` builder-chain (intentional). doc-check 36/36.

## 2026-06-30 (Tue) — v4.54.0: top type-aware ranking, kill _row_number, Alt-r timing

Three things, all from the user comparing CLI output to generated typed code.

**`top` ranked strings wrong.** `top -field a_name` (a string field) returned
arbitrary rows: the execution path keyed via `extractNumeric`, which returned 0
for every non-number, so all strings tied at 0. The typed codegen always
compared by the field's native Go type (string → lexicographic), so it was
right and the CLI was silently wrong. Fixed by ranking with `ssql.CompareAny`
(the comparator `sort` uses). Added comparator-based `ssql.TopByFunc`/
`BottomByFunc` (bounded heap, O(N·log K)) to back it; deleted the now-dead
`extractNumeric`. Execution now matches codegen — locked with a `top_string_asc`
corpus case across record/typed/parallel.

**Killed `_row_number`.** `ssql.ReadCSV`/`ReadCSVFromReader`/`from xlsx` had
attached a hidden `_row_number` column at read time since the very first commit.
It leaked into to-table/to-csv/to-json and diverged from typed mode (which never
had it) — the user "never liked it", so: removed from both io.go readers and
xlsx.go, dropped the now-dead consumer guards (helpers.go fieldNames filter,
join.go right-field skips). Kept arrow.go's general `_`-prefix skip (defensive)
and repointed its test to a neutral `_internal` example so the term appears
nowhere in code. Record and typed output now match. Tradeoff noted in CHANGELOG:
`window -row-number` is the way to get row numbers now.

**Alt-r timing.** Alt-r regenerates typed Go from READLINE_LINE and runs it, so a
shell `time` never wrapped the real work. Added `generate go -time`: runGoSource
already compiles then runs as two steps, so it now reports both to stderr —
`[ssql: compiled in 1.4s, ran in 7ms]` — compile separate from run so the run
figure is the compiled pipeline's true speed. Alt-r passes `-time` and echoes it
inline on success (errors still go to the popup).

Gates: full corpus (record/typed/parallel) green, cmd/ssql -short green (260s),
root/commands/wasm/typed green, -race clean, doc-check 36/36. Also shipped
earlier today: v4.53.0 (heap top-k in typed mode + generate-go -mode completer).

## 2026-06-30 (Tue) — v4.54.1: typed `to table` honours -max-width

Follow-up to the top/_row_number work: user noticed record vs generated-typed
`to table` truncated differently. Record mode defaults `-max-width 50` and
truncates; typed codegen emitted `typed.WriteTableToWriter(seq, w)` which had no
width concept and never truncated — and `-max-width` was silently dropped in
typed mode entirely.

variadic `maxWidth ...int` (back-compatible — no arg = no truncation, so old
generated code keeps compiling and behaving the same), threaded it into the
shared `writeTableLines` formatter (truncation mirrors `ssql.DisplayTable`:
`v[:maxWidth-3]+"..."`, guarded for tiny caps), and made `generateTypedToTableCode`
pass the flag value (default 50). Record and typed now render byte-identical.

## 2026-06-30 (Tue) — declutter flag completion (autocli v4.12.0)

User: completing `ssql from csv -<TAB>` drowned the command's own options under
global flags, short-form aliases, and the -help/-man/-completion-script set
(~17 candidates for 6 real options). Prototyped + shipped "Direction A" in
autocli:

- only a flag's PRIMARY name shows on a broad `-<TAB>`; aliases appear only on a
  specific matching prefix (`-dt<TAB>` still completes -dt).
- inherited root globals get a new unexported `FlagSpec.demoted` (set on COPIES
  via `demotedRootGlobalFlags`, used only at the 3 completion merge-sites — help/
  man/exec keep the originals) and are likewise prefix-only at subcommand level.
- built-in meta flags collapse to one foregrounded `--help`; -help/-h/-man/
  -completion-script are prefix-only.
- positional names (FILE, FIELDS) no longer leak into flag completion.
- folded the duplicate completeFlags/completeFlagNames into one completeFlagSet.

Result: `from csv -<TAB>` → `-default-type -generate -merge-schemas -source -type
-unordered --help`. Foreground matching is byte-identical to before, so nothing
that completed before stopped completing. Generic — every autocli CLI benefits.

## 2026-06-30 (Tue) — N-way differential equivalence harness + record/SQL top fixes

**The bug that motivated it.** User's `top -field a_name` (string) gave different
results in record-mode Go codegen vs typed. Root cause was the SAME string-vs-
numeric bug from v4.54.0, but in two paths I'd missed: (1) the **record-mode Go
codegen** template still emitted `ssql.BottomBy(..., float64 GetOr(f,0.0))`
(coerces strings to 0) — fixed to `ssql.BottomByFunc + ssql.CompareAny`, matching
execution + typed; (2) **`generate sql`** `translateTop` was worse — it looked
for the long-removed `-by` flag (so NO `ORDER BY` was ever emitted) and treated
`args[0]` as N (so `-asc` became `LIMIT -asc`). Rewrote it → `ORDER BY FIELD
DESC|ASC LIMIT N`; DuckDB-verified. All four paths now agree.

**Why it kept happening → build a real gate.** `top` had 4 result-producing
paths and the smoke corpus (Contains/Excludes) couldn't tell them apart —
`top_string_asc` expected Alice/Bob and the *buggy* output also contained
Alice/Bob (employees are alphabetical, so "first-N" == "sorted-N"). So I built
`cmd/ssql/equivalence_test.go` (`TestPipelineEquivalence`): one pipeline → every
lane (exec / go-record / go-typed / go-parallel / generate-ssql) → canonical
JSONL via `to jsonl` → normalise the *legitimate* differences (column order:
record alphabetical vs typed struct order; int/float via json→float64) →
assert **byte-identical**, ordered-list when the pipeline defines order else
multiset. Fixtures are **shuffled** with distinct values (new `corpusShuffledCSV`)
so wrong selection diverges; `Golden` gives an impl-independent oracle (catches
"all lanes agree but all wrong" — how the exec bug originally hid).

**Proved it has teeth**: temporarily reverted the record-codegen fix → the
harness failed with the exact diff (`exec: Tokyo,Quito,Paris` vs `go-record:
Cairo,Lima,Mumbai`), pointing at the lane. Restored; all 8 cases × 5 lanes green.

Tests: strengthened TestTopGeneration/Asc (assert TopByFunc+CompareAny, reject
float64 key); new TestTranslateTopSQL; new corpus `top_string_desc`
(discriminating). CLAUDE.md: recorded TestPipelineEquivalence as the differential
gate for any change to a command's results. Uncommitted, on top of the
autocli-v4.12.0 completion-declutter bump.
