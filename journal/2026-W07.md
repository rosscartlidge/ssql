### Fix: Update Command Schema Merge for New Fields

When `update -set tier gold` adds a new field to records with a schema header, the new field was silently dropped by downstream commands (`to table`, `to json`, etc.) because the schema header still listed only the original fields.

**Fix:** Before writing output, compare `-set`/`-set-expr` fields against the input schema. If any are new, clone the schema and add them with inferred types.

### WASM Module for In-Browser Data Transformations - Phase 5

Added a WebAssembly module that exposes ssql data operations to JavaScript, enabling the `to explore` data explorer to run real ssql transforms client-side instead of reimplementing them in JS.

**Architecture:**
- WASM module registers 6 global JS functions via `syscall/js`
- Explorer HTML inlines the JS runtime (~21KB), loads `ssql.wasm` (~15MB raw, ~3MB gzip) via fetch
- Falls back to JS aggregation if WASM fails to load
- Green "WASM" badge appears in explorer header when module is active

**New files:**
- `cmd/ssql-wasm/main.go` - WASM entry point, registers ssqlWhere/Sort/GroupBy/Distinct/Limit/Pipeline
- `cmd/ssql-wasm/bridge.go` - JSON↔Record conversion using ReadJSONFastFromReader + AppendJSON
- `cmd/ssql-wasm/operators.go` - Thin wrappers around ssql.Where, SortBy, GroupByFields, Aggregate, DistinctBy, Limit, Offset
- `cmd/ssql-wasm/js/ssql-wasm.js` - JS wrapper class (SsqlWasm) with clean API

**Modified files:**
- `chart.go` - Added WasmEnabled/WasmExecJS/SsqlWasmJS to ExploreConfig; template inlines JS when WASM enabled; aggregation uses WASM with JS fallback; added CopyExploreWasmFile()
- `cmd/ssql/commands/to.go` - Added `-wasm` flag to `to explore`; loads JS files and copies ssql.wasm alongside HTML
- `Makefile` - Added `wasm` target (GOOS=js GOARCH=wasm build + wasm_exec.js copy)
- `.gitignore` - Added WASM build artifacts

**Design decisions:**
- Build-tagged files (`//go:build js && wasm`) so `go build ./...` excludes WASM package
- JS files inlined in HTML template (small enough at ~21KB) to avoid extra file management
- Only `ssql.wasm` binary copied as separate file (15MB too large to inline)
- Comparison operators duplicated from CLI helpers.go (can't import `commands` package from WASM `main`)

**CLI usage:**
```bash
make wasm
ssql from data.csv | ssql to explore -wasm cmd/ssql-wasm/ssql.wasm output.html
```

- `doc/cli-codelab.md` - Added Interactive Data Explorer and WASM sections; fixed old `chart` command syntax to `to chart`; added `to explore`/`to heatmap`/`to wav` to Available Commands list
- `doc/api-reference.md` - Added Data Explorer subsection with ExploreConfig, DataExplore, CopyExploreWasmFile docs and examples

**Note on go:wasmexport:** Investigated using Go 1.24's `go:wasmexport` directive instead of `syscall/js`. It only works with `GOOS=wasip1` (server-side WASM runtimes), not `GOOS=js` (browser). The `syscall/js` + `wasm_exec.js` approach remains the only supported method for browser WASM in Go 1.24.

### Animated Heatmap and Histogram Command (to animate)

Added `to animate` command — "MPEG for data" — a self-contained HTML file where a heatmap or histogram evolves frame-by-frame with video-player controls.

**New features:**
- Animated heatmap mode: records grouped by frame field, each frame rendered as a 2D grid with global Z range
- Animated histogram mode: records grouped by frame field, each frame rendered as a bar chart

- Code generation support (`-generate` / `SSQLGO=1`)
