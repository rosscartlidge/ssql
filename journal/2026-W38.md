## 2026-09-14 (Mon) — popups without tmux, and the Alt-h quoting bug it found

Ross: "build the less popup fallback" (DFC127 §3). `_ssql_show_help`:
in tmux unchanged; else, when stdout+stdin are a terminal and the text
has more lines than the terminal minus three (`$LINES`, else `tput
lines`, else 24), `${PAGER:-less -R} < tmpfile` — the alternate screen
makes it read like a popup and `q` restores the line; shorter answers
stay inline (a flag's help is quicker to read there). `SSQL_POPUP=
inline|pager` forces either; every pty test that scrapes the terminal
exports `inline`, and a new `TestHelpPagerPTY` (24-row pty, PAGER = a
script that records stdin) asserts the reference goes to the pager and
`-sum`'s help stays inline.

Writing that test exposed a bug nobody had hit: `_ssql_help_at` split
the stage into words with `read -ra`, which ignores quotes, so an
`-if-expr 'salary > 1000 && bucket(ts, ` became five words and the
cursor landed past the expression argument — Alt-h showed only the
flag. Ross's earlier manual check used `'upper(trim(name` (no spaces),
which is why it seemed fine. Fix per DFC115: stop tokenising in bash.
`ssql -help-at-cursor BEFORE` finds the stage (paren-aware) and the
words (quote-aware `tokenizeStageOpen`; an unclosed quote keeps its
trailing space — the first cut appended an empty "new word" and missed
again), then the shared `helpAtWords`. The binding is now four lines.
Two test-writing gotchas: `PAGER` is word-split by the shell, so a
quoted command in it breaks — use a script path; and a python driver's
`open(...).write` needs the pty size set AFTER fork (TIOCSWINSZ).
Docs: codelab §1, README key table note, tmux page §5, DFC127.

**Then the proxy said no.** All six `go install …@v4.98.0` retries:
`create zip: malformed file path "doc/codelab-data/select 1 as a, 'x'
as b": invalid char '\''`. On 2026-09-12, checking the DuckDB JSON
shapes for the codelab, a `duckdb` call took its SQL as a *database
filename* and wrote a 12 KB DuckDB file with that name into
codelab-data; `git add doc/` swept it into 9ecffec. Nothing noticed:
the codelab embed lists explicit globs (`*.csv *.parquet *.log README.md
codelab-run.sh`) so the binary never carried it, every gate passed, the
tag built. Only the proxy's zip step — which runs after the immutable
tag exists — applies `module.CheckFilePath`. Two lessons: (1) `git add
DIR` on a data directory after a session that ran ad-hoc tools in it is
how junk gets in — `git status` the directory first; (2) the release
gates had no check that mirrors the proxy's. Now they do:
`TestModuleZipPaths` (root package, `module_zip_test.go`) feeds `git
ls-files` through `golang.org/x/mod/zip.CheckFiles`, so the exact rule
set the proxy applies runs in the unit gate. Watched it fail on the
stray file, then pass after `git rm`. x/mod is now a direct dependency
(test-only import). v4.98.0 stays tagged (never re-tag); v4.98.1 is the
installable one — debs/WebVM/playground for 4.98.0 were correct binaries,
rebuilt anyway under the new version.
