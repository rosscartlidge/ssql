### Docker GPU Build Fixes

Fixed issue where pre-built `.so` file was being copied into Docker container, causing CUDA library to not be rebuilt.

**Files created:**
- `.dockerignore` - Exclude pre-built binaries, `.so` files, and development artifacts from Docker context

**Files modified:**
- `Dockerfile.gpu` - Added `make clean` before `make` to ensure fresh build

**Issue:** Docker was copying the locally-built `libssqlgpu.so` into the container. Since `make` saw the file already existed, it skipped compilation with "Nothing to be done for 'all'". The local `.so` was built with `-arch=native` for RTX 5090, incompatible with Docker's build environment.

**Solution:**
1. Added `.dockerignore` to exclude `*.so` files from Docker context
2. Added `make clean && make` in Dockerfile to force rebuild

**Verified working:**
```bash
# Docker container with GPU access
docker run --gpus all ssql:gpu version
# Output: ssql v4.8.12 (gpu: yes)

# Extracted binary
make docker-gpu-extract
LD_LIBRARY_PATH=. ./ssql_gpu version
# Output: ssql v4.8.12 (gpu: yes)

# GPU tests pass

# PASS
```

### TSV Format Support

Added TSV (Tab-Separated Values) format support. TSV is simpler and more predictable than CSV:
- Field names must be valid identifiers (letters, digits, underscore)
- Separator is auto-detected from first non-identifier character in header
- No quoting or escaping needed - just split on separator

**Files created:**
- `tsv.go` - TSV read/write functions, separator detection
- `tsv_test.go` - Comprehensive tests for TSV operations

**Files modified:**
- `cmd/ssql/commands/from.go` - Added `.tsv` extension detection and `-format tsv` support
- `cmd/ssql/commands/to.go` - Added `to tsv` subcommand with `-separator` flag

**New ssql package API:**
- `ReadTSV()` / `WriteTSV()` - File operations
- `ReadTSVFromReader()` / `WriteTSVToWriter()` - Stream operations
- `DetectTSVSeparator()` - Auto-detect separator from header
- `ExtractFieldsFromTSV()` - Extract field names from TSV file

**CLI usage:**
```bash
ssql from data.tsv                     # Auto-detect separator
ssql from data.tsv | ssql to tsv       # TSV round-trip
ssql to tsv -separator '|' output.psv  # Custom separator
```

### TSV Performance Optimization

Profiled TSV reader and found 61% of allocations came from `strconv.syntaxError` - error objects allocated when `ParseInt`/`ParseFloat` fail on non-numeric strings like "Alice" or "NYC".

**The fix:** Check if a string looks numeric before calling parse functions.
- Added `looksLikeInt()` function for quick character scan
- Only call `ParseInt`/`ParseFloat` when likely to succeed

**Benchmark results (10K rows):**
| Metric | Before | After | Improvement |
|--------|--------|-------|-------------|
| Time | 4.47ms | 1.42ms | 3.1x faster |
| Allocations | 230K | 50K | 4.6x fewer |
| Memory | 5.6MB | 1.5MB | 3.7x less |

**Real-world (1M rows, 33MB file):**
| Format | Time | Notes |
|--------|------|-------|
| CSV | 0.59s | Go's encoding/csv |
| TSV | 0.44s | **34% faster** |

**Key learning:** Profiling revealed an unexpected bottleneck - failed parse attempts allocating error objects. The fix was simple once identified.
