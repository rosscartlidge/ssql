### Distributed Shard Catalog Design

Created `doc/research/distributed-shard-catalog.md` — design for discovering and locating shards of a dataset across multiple files and machines accessible via SSH.

**Key design decisions:**
- Catalog is a CSV file mapping shards to `host:path` with optional range metadata for partition pruning
- Range columns (`date_from`/`date_to`) and exact-value columns (`region`, `country`) enable skipping irrelevant shards before any SSH connections
- Four distribution patterns: single catalog file, per-machine catalogs merged at query time, shared location (git/NFS), auto-discovery via SSH glob
- Ties into existing `merge` command for ordered output across shards (`--merge-sort`)
- Push-down via `--remote` for map-reduce style two-level aggregation

**Usage:**
```bash
ssql from --catalog shards.csv -where date ge 2025-03-01 | ssql to table
```

### LXD Container Networking Fixes

Fixed two separate networking issues with the LXD test containers.

**Issue 1: No outbound internet from containers**

Containers could reach the host (SSH, DHCP worked) but couldn't access the internet. Diagnosis steps:
1. LXD NAT was enabled (`ipv4.nat: "true"` on lxdbr0) — not the problem
2. IP forwarding enabled (`net.ipv4.ip_forward = 1`) — not the problem
3. Changed UFW `DEFAULT_FORWARD_POLICY` from DROP to ACCEPT — didn't help
4. tcpdump showed packets leaving host with correct masqueraded source IP (192.168.86.44) but no replies
5. Discovered host itself couldn't reach 93.184.216.34 (old example.com IP) — red herring, that IP no longer responds
6. Real outbound traffic worked fine from host (`curl http://example.com` → 200)

**Issue 2: DNS resolution failing in containers**

Containers used systemd-resolved (127.0.0.53) which forwarded to LXD's dnsmasq on 10.131.56.1, but queries timed out.
1. Added `raw.dnsmasq "server=192.168.86.1"` to forward to router DNS — config written to `/var/snap/lxd/common/lxd/networks/lxdbr0/dnsmasq.raw` but still didn't work
2. Verified router DNS worked from host: `dig +short example.com @192.168.86.1` → success
3. Suspected Tailscale (100.100.100.100 MagicDNS) interference — not the direct cause

**Root cause:** nftables rule ordering conflict between LXD and UFW. In LXD's own `inet lxd` table:
```
iifname "lxdbr0" udp dport 53 accept    ← accepts DNS on lxdbr0
...
ip daddr 10.131.56.1 udp dport 53 drop  ← then drops DNS to the bridge IP
```
In nftables, `drop` in any chain is **final** (packet gone), but `accept` only passes to the next chain. So LXD's accept was overridden by a drop rule evaluated later. UFW's default deny policy compounded this.

**Fix:** `sudo ufw allow in on lxdbr0` — allows all traffic from lxdbr0 through UFW, so packets reach dnsmasq before any drop rule fires.

**Result:** Containers now have full internet access (DNS + TCP/HTTP working).

**Key lesson:** When debugging nftables with multiple tables (LXD, UFW, Tailscale, Docker), remember that `accept` is not final across chains — only `drop` is. A packet can be accepted by one chain and dropped by another.

### Design Doc: Parameterized Code Generation

Created `doc/research/parameterized-codegen.md` — design for making generated programs accept command-line flags instead of hardcoding literal values.

**Key ideas:**
- Three tiers: file paths (always parameterize), filter values (when present), structural params (never)
- Parameters declared per-fragment via new `Params` field on `CodeFragment`

- Filter value naming from field+operator (e.g., `-if date ge 2025-02-01` → `-date-ge` flag)
- Turns generated programs from one-shot scripts into reusable tools

### SSH + Catalog Completion System

Implemented comprehensive tab completion for remote data sources.

**`from ssh` — host completion + connection warmup:**
- HOST completer reads `~/.ssh/config` for host aliases
- When narrowed to a single host, background-starts `ssh -N -f host` to warm the multiplexed connection
- By the time user tab-completes PATH, the connection is ready

**`from ssh` — remote field discovery:**
- PATH completer SSHs to fetch `head -1 /path` from the remote file
- Parses CSV header and emits `field_cache` directive
- Downstream `where -if <TAB>` shows remote file's field names
- Uses `/usr/bin/head` (absolute path per security rules)

**`from catalog` — smart catalog completion:**
- Catalog FILE completer emits catalog metadata columns (not raw CSV headers)
- Range columns collapsed: `date_from`/`date_to` → `date`
- Structural columns (`host`, `path`, `format`) included as valid pruning targets
- `fields` column excluded (schema hint, not data)

**`from catalog` — value completion for `-if`:**
- `-if host eq <TAB>` → shows actual host values (`ssql-node1`, `ssql-node2`, `ssql-node3`)
- `-if date ge <TAB>` → shows `date_from` values (`2025-01-01`, ...) so users see the format
- Custom `CompletionFunc` with fallback: tries exact column, then `field_from` for range fields

**Catalog `fields` column:**
- Added optional `fields` column to catalog CSV format

### Union + Multi-SSH Code Generation Fix

Fixed three bugs in code generation for `union -file <(from ssh ...)` pipelines:

1. **Variable collisions**: Multiple SSH init fragments all declared `remoteCmd`, `sshCmd`, `sshStdout`. Fix: wrap each subprocess in a `func` fragment — each becomes its own function, encapsulating all internal variables.
2. **Union not Chain-compatible**: `Concat` isn't a filter function. Fix: generate a closure `func(input iter.Seq[...]) iter.Seq[...] { return Concat(input, source()) }` that works in `Chain()`.
3. **Func name dedup**: Multiple union commands in a pipeline each generated `unionSource1`. Fix: assembler deduplicates with `_2` suffix, claiming stmt fragments in order to update the correct reference.

Also fixed `extractFilter` to handle `}(` pattern (closure application) alongside the existing `)(` pattern.

**Param dedup fix**: `collectParams` now updates fragment code when renaming params (e.g., `*flagHost` → `*flagHost2`), ensuring func body code references the correct deduplicated flag variable.

**Schema header leak fix**: `ReadJSONFromReader` now skips `_schema` header lines, matching the behavior of all other JSONL readers. This was causing a phantom empty-region row in generated code output.

### Parquet Format Support

Added Parquet read/write using the Apache Arrow Go `pqarrow` package (already a dependency via Arrow support).

```bash
ssql from parquet data.parquet | ssql to table          # read
ssql from data.csv | ssql to parquet output.parquet     # write
ssql from data.parquet                                  # auto-detected from extension
```

- Read via `pqarrow.ReadTable` → Arrow Table → ssql Records
- Write via ssql Records → Arrow batch → `pqarrow.WriteTable` with Snappy compression
- No stdin support (Parquet is random-access, footer-based format)
- Code generation for both `from parquet` and `to parquet`
- Registered as `from parquet` / `to parquet` subcommands + bare form extension detection

### DuckDB SQL Generation (`generate-sql`)

New `generate-sql` command produces DuckDB-compatible SQL from the same pipeline fragments as `generate-go`. No changes needed to existing commands — the SQL assembler parses the `Command` string from each fragment.

```bash
(export SSQLGO=1; ssql from data.csv | ssql where -if age gt 25 | ssql group-by dept -sum salary total | ssql to table) | ssql generate-sql
# Output:
# SELECT dept, SUM(salary) AS total
# FROM 'data.csv'
# WHERE age >= '25'
# GROUP BY dept
# ;
```

Pipe directly into DuckDB:
```bash
... | ssql generate-sql | duckdb
```

**Supported commands:**
- `from csv/tsv/json/parquet/arrow/xlsx FILE` → `FROM 'file'`
- `where -if field op value` → `WHERE` with operator translation
- `where -if-expr` → pass-through (SQL expression syntax)
- `group-by` with `-count/-sum/-avg/-min/-max/-collect` → `SELECT ... GROUP BY`
- `sort` / `sort -desc` → `ORDER BY`
- `limit` / `offset` → `LIMIT` / `OFFSET`
- `top N -by field` → `ORDER BY field DESC LIMIT N`
- `join -using/-on` → `JOIN ... USING/ON`
- `distinct` → `SELECT DISTINCT`
- `include` → `SELECT field1, field2`
- `exclude` → `SELECT * EXCLUDE (field)` (DuckDB-specific)
- Multi-clause OR (`+` separator) → `WHERE (...) OR (...)`

**Files created:**
- `cmd/ssql/commands/generate_sql.go` — `RegisterGenerateSQL`, `assembleSQL`, translators for each command type

**Files modified:**
- `cmd/ssql/main.go` — register `generate-sql`
