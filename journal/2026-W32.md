## 2026-08-09 (Sun) — ported generate-ssql negation fix from the web-session branch

While away, a claude.ai/code web session independently fixed the v4.56
`+if`/`+if-expr` negation class on branch
`claude/journal-files-context-ynn0os` (25a61cf) — the same sweep later done
locally as 2d890de and shipped in v4.56.1. The two are rival rewrites of the
same files (different shared-helper names: web `parseExprConditions` vs
main's shipped `parseExprConds`), so merging the branch was wrong. Instead:
keep main canonical, port the branch's one UNIQUE piece.

**What was uniquely on the branch:** `cmd/ssql/commands/generate_ssql.go` —
the optimiser's where round-trip didn't recognise `+if`/`+if-expr`
(`parseWhereArgs` fell through to default and skipped the tokens), so ANY
rewrite rule that rebuilt a where clause (predicate simplification, reorder,
catalog extraction, join pushdown) silently dropped the negated conditions
from the optimised pipeline. Confirmed live on main: v4.56.1's equivalence
cases all use single-condition wheres, which never trigger a rebuild — the
ssql-opt lane passed while the bug sat one rewrite away. Main hadn't touched
the file since the branch point (16bc3b7), so the port was a clean
`git checkout 25a61cf -- cmd/ssql/commands/generate_ssql.go`.

**Gates, watched failing first:** two new equivalence cases —
`where_negated_survives_simplify` (`-if pop gt 5 -if pop ge 8 +if pop lt 12`:
range tightening triggers the rebuild; also proves the negated bound stays
OPAQUE to tightening) and `where_negated_expr_survives_reorder` (`ne` is
cheaper than `gt`, reorder triggers the rebuild). Both failed exactly and
only in the ssql-opt lane pre-port, green in all lanes post-port. Also
ported `TestNegatedConditionGeneration` (branch's emitted-source pinning
test — main's emissions matched its expected strings verbatim) extended
with two `generate ssql` round-trip subtests, verified discriminating
(optimiser output shows the rule fired AND the `+` token survived).
Full equivalence + permutations + corpus + commands tests + vet green.

**Found on the way (TODO'd, not fixed):** record codegen mis-references
flags for duplicate field+op conditions — `-if pop gt 5 -if pop gt 8`
declares `flagPopGt`/`flagPopGt2` but emits both references as
`flagPopGt2` (first value silently replaced; three duplicates → undeclared
`flagPopGt32`, doesn't compile). Invisible for ANDed same-direction bounds,
wrong for `+if` mixes and OR clauses. The first draft of the simplify
equivalence case tripped over it; reshaped the case to distinct operators
so it gates the optimiser bug, and recorded the naming bug in
doc/research/TODO.md. Also ported the branch's TODO about `-catalog` `-if`
pruning flags having no negated form.
