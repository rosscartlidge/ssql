## 2026-08-11 (Tue) — gh-pages playground deploy automated

Closed the long-standing TODO: playground deployment to `gh-pages` is now a
GitHub Actions workflow (`.github/workflows/playground.yml`) instead of the
manual build-on-main / copy-to-/tmp / `git checkout gh-pages` dance we ran by
hand three times last week alone (v4.57–v4.59).

**How it works.** On push to `main` (path-filtered to `**.go`, `go.mod`,
`go.sum`, `cmd/ssql-playground/**`, and the workflow itself — doc-only and
`.deb`-baking pushes don't trigger it) plus `workflow_dispatch`: checkout main,
`make playground` (plain Go `js/wasm` slim build, no TinyGo — CI-friendly),
checkout `gh-pages` into a `ghp/` subdir, copy exactly three files
(`ssql-playground.wasm`, `wasm_exec.js`, `playground.html`), commit and push
only if they changed. Everything else on gh-pages (`data/`, `fs-polyfill.js`,
the gpu demo) stays untouched and remains manually deployed.

**Design notes for future-me:**
- The CI checkout of gh-pages into a subdir sidesteps the shared-working-tree
  gotcha entirely (that hazard only exists locally where both branches share
  one tree). The branch's mirrored `.gitignore` is irrelevant here anyway —
  all three targets are already *tracked* on gh-pages, and ignore rules never
  apply to tracked files.
- `git add` names the three files explicitly (not `-A`), so the workflow can
  never sweep anything unexpected into the branch.
- `permissions: contents: write` with the default `GITHUB_TOKEN` is enough to
  push to gh-pages — no PAT needed (unlike goreleaser's Homebrew-tap push).
- Concurrency group `deploy-playground` with `cancel-in-progress` so a rapid
  push series only deploys the latest.

**Doc updates:** `claude/playground.md` now leads with the automation and
demotes the manual steps to fallback; CLAUDE.md post-release checklist replaces
"update gh-pages branch" with "verify the workflow ran"
(`gh run list --workflow=playground.yml -L 1`); TODO item checked off.

The commit landing this change is itself the live test — it touches the
workflow path, so the first automated deploy fires on push.

## 2026-08-11 (Tue) — `limit 0` = no limit (pass-through dial)

Ross's idea: keep a `limit N` sampling stage permanently in a pipeline and
dial it to `0` for full runs, instead of editing the stage out. So `limit 0`
now passes everything through (previously "limit must be positive"), and in
code generation a zero-valued stage emits NO fragment — it vanishes from
generated go, sql, and ssql alike, since all three generators are
fragment-driven. `offset 0` (already accepted, but it emitted a useless
zero-skip fragment) gets the identical treatment.

Testing per the multi-backend doctrine: `limit_zero_passthrough` equivalence
case (`where | offset 0 | limit 0` with a golden — all lanes incl. DuckDB
must return exactly the where result) plus `TestLimitZeroSkipsGeneration`
(12 subtests pinning no Limit/Offset marker in generated go/sql/ssql across
record+typed modes). Both gates watched failing under deliberate sabotage
(re-enabled fragment emission → 6 leak failures + equivalence divergence,
because generated code then ran `Limit(0)` = zero rows). Bonus lesson: the
generation test's first version failed on its own fixture *filename*
containing "limit" — reject-substring oracles need token-ish patterns.

Docs: codelab pagination section, CHANGELOG under [Unreleased].

## 2026-08-12 (Wed) — playground Tab completion (and the fs-polyfill path bug)

Tab in the playground textarea now drives the CLI's own completion engine
(`-complete N words…` — the exact protocol bash uses) through the existing
`ssqlExec` bridge; no new WASM exports. Bash-style UX in ~120 lines of JS:
single candidate inserts with a trailing space, multiple extend to the
longest common prefix and open a popup at the caret (mirror-div pixel
positioning; arrows/Tab cycle, Enter/click accept — mousedown not click, so
the textarea keeps its caret — Esc closes). Engine hint entries (`<VALUE>`,
`Use-Ctrl-O`) are surfaced as a status-line message, not inserted. The
caret math is shared with Alt-h via a `cursorContext()` helper.

The real story was FILE completion. It returned nothing in WASM while
working natively. The debugging ladder, each rung disproving a theory:
harness (flags only) → JS-level polyfill probes (open/fstat/readdir all
fine) → a purpose-built goprobe.wasm calling os.ReadDir (empty, no error)
→ syscall-level ReadDirent (works! bytes present) → os.File.Readdirnames
(works!) → so the loss was in os.ReadDir's DirEntry layer. Reading
os/dir_unix.go: on js/wasm `direntType` is always unknown, so ReadDir
LSTATS each entry as `parent + "/" + name` = `"./employees.csv"` — and the
polyfill's store keyed `"./x"`, `"/x"`, `"x"` as three different files, so
the lstat ENOENTed and Go dropped every entry as "file disappeared between
readdir and stat". Silent empty, no error anywhere.

Fix: a `norm()` canonicalizer applied at every fs-polyfill path entry point
(open/stat/readdir/unlink/rename/truncate + the _fsWriteFile/_fsReadFile
helpers), plus directory-fd support (open("." ) used to ENOENT; close() must
not flush a dir fd or it materializes "." as an empty file). The procsub
FIFO check moved to the normalized form ("dev/fd/") — guarded by a new
procsub-join harness scenario since that's the subtle thing a path change
could break. fs-polyfill.js added to the deploy workflow's copy list (it
was previously never redeployed).

Harness now 14 scenarios, all green. The playground blurb no longer
apologizes for missing tab completion — it advertises it.

## 2026-08-12 (Wed) — playground pipeline-aware field completion (Ctrl-O, but better)

The last of the playground completion trio. `-complete-source` (already in
the deployed protocol) names the upstream feeding the cursor — paren-aware,
including join right-side fields; the JS pipeline simulator runs it under
`SSQL_MODE=schema` and pipes into `ssql generate schema` for the field
names, which feed the same popup as Tab completion.

Two design notes:
- **WASM env is frozen at go.run()**, so schema mode couldn't be set the
  bash way. `ssqlExec` gained an optional third argument: a per-invocation
  env object, applied via os.Setenv and restored after Execute (safe:
  single-threaded, synchronous). Threaded `env` through
  parsePipeline/resolveProcessSubstitutions so procsubs inside a schema-mode
  upstream also run in schema mode.
- **The browser beats bash here.** The CLI needs a separate Ctrl-O
  keybinding because bash scopes Tab completion to one command — it can't
  see the pipeline. The playground's Tab sees everything, so when the
  engine answers a field slot with the Use-Ctrl-O hint, Tab transparently
  completes from the live schema instead of showing the hint. Ctrl-O is
  also bound for CLI parity (preventDefault is load-bearing — browser
  default is "open file").

Harness now 16 scenarios. The pipeline-aware gate is the money shot:
`from employees.csv | group-by dept -count cnt | sort <Tab>` must offer
dept+cnt and NOT salary. Sabotage lesson: removing SSQL_MODE=schema did
NOT fail the gates — exec-mode upstreams emit `_schema` headers that
`generate schema` also reads, so schema mode is the fast path (headers
only), not the only correct path; the discriminating sabotage was breaking
the prefix filter (caught by two gates). Playground blurb updated again —
field completion moved from the "real CLI adds" list to the featured list.

## 2026-08-12 (Wed) — DFC106: the DFC system's own DFC (+ two dfc.py bugs)

Exercising the fresh tooling immediately caught two bugs in dfc.py:
1. **`\s*$` in the metadata regexes** — \s matches newlines, so each

   block spacing. Fix: `[ \t]*$`.
2. **Stamping feedback loop** — after committing the backfill, every doc's

   historical dates intact. Costs ~12s (per-file git show walks) — fine

## 2026-08-12 (Wed) — schema-mode TSV delimiter detection (Ctrl-O on pipe-delimited files)

Ross asked whether TSVs handle non-tab separators. Answer: yes — `from tsv`
auto-detects the delimiter (first non-identifier header byte: | : , ;

Fix: exported the detection as `lib.DetectDelimInHeader` (refactoring
`detectTSVDelim` to use it — one rule, every path) and the schema-mode
branch now detects + parses the header via encoding/csv with that
delimiter (matching the real readers' quote handling, and how the CSV
schema branch already worked). Two new cases in `TestSchemaModePipeline`
(tab + pipe); watched the pipe case fail under a hard-tab sabotage.

## 2026-08-15 (Fri) — playground completion as you type

Ross asked what I thought of as-you-type completion; built it. A debounced
(150ms) input listener runs the existing completion path and shows the
popup PASSIVELY: typing keeps filtering, Tab or click accepts, Escape
suppresses for the current word (keyed by word-start offset), and — the
design point that mattered most — Enter is never stolen by a passive
popup; it only accepts after arrow-activation (moveCompletionSel flips
passive→active). All popups now start passive, including Tab-opened ones,
for one uniform rule; the only harness casualty was the value-quoting
scenario that pressed bare Enter on a fresh popup — updated to arrow
first, which IS the new contract.

Cost controls: schema-mode field runs cached by upstream-pipeline text
(cleared on upload and on run, since runs can rewrite files); the auto
path passes cheapOnly to completionCandidates, which skips value sampling
when the derived source exceeds 1MB (Tab still samples anything). ssqlExec
is synchronous on the main thread, so the debounce is what keeps typing
smooth; a latency harness probe pins one flag-completion round-trip under
a generous 500ms ceiling to catch pathological regressions.

Harness: +7 scenarios (auto-popup, Enter-not-stolen via dispatchEvent's
preventDefault return, Tab-accepts, arrow+Enter accepts, Escape
suppression, field auto-suggest, latency), 35 total. Header hints updated:
"Suggestions appear as you type".

## 2026-08-15 (Fri) — program-word completion fix (user-found, minutes in)

Ross, trying as-you-type: typing "ssql" popped the SUBCOMMAND list, and
