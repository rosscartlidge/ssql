Ross skipped the adoption round (missed GopherCon Seattle; aiming for

2a shipped: `ssql serve -listen-http ADDR -dir DIR` —
- /api/execute: strict tokenizer (quotes group, NO shell — redirection,
  procsub, `;`/`&`/backtick/`$()` are loud errors, `$foo` is inert) →
  per-stage self-exec chain (os.Executable), stdout→stdin, streamed
  response. Failures before the first output byte are clean 422s with
  stderr; after that they ride X-Ssql-Exit-Code/X-Ssql-Error trailers
  (a field typo fails AFTER the _schema header is out — learned by
  test). Departure from DFC079 rev-1: self-exec, not in-process
  cli.ExecuteWith — exec-lane semantics by construction.
- /api/cursor: cursor-protocol passthrough (allow-listed verbs) — the
  exact surface ssql-ui.js needs for 2b completion/help over HTTP.
- /api/files, /api/health; bearer -token (required to bind
  non-loopback — server refuses to start otherwise); -http-timeout;
  PATH now optional (HTTP-only serve works; SSH protocol unchanged).

Gates: TestSplitServePipeline (14-case table), TestServeHTTP*
integration (real binary on :0; execute-matches-direct differential
oracle — sabotage-verified; token auth; startup refusal), slim + wasm
cross-builds. Gotchas: shared stderr bytes.Buffer across stages was a
data race (per-stage buffers); first-read hold-back must be ONE Read,
not io.ReadFull (would stall streaming); `-complete` argv excludes the
leading "ssql".

## 2026-08-19 (Wed) — serve Phase 2b: the served explore workspace

"Looks great - lets proceed." 2b landed same-day because the design
collapsed into almost nothing: serve does NOT embed or re-render
anything — `GET /explore?file=X` (or `?pipeline=…`) runs
`<head> | ssql to explore TMP` through the 2a stage chain and serves
the file. The workspace page is BYTE-IDENTICAL to a locally generated
artifact (asserted by test against a fresh local `to explore` run;
sabotage-verified) — one implementation, zero drift by construction.
`GET /` is a minimal index linking each data file to its workspace
(?token= threaded through, the Jupyter pattern). ?file= is
allow-listed against the dir listing (traversal → 404);
?pipeline= goes through the same strict tokenizer as /api/execute —
so `?pipeline=ssql from ssh node1 /data/x.csv -- where …` already
gives the DFC108 three-tier demo: browser workspace over
remote-reduced data.

Refactor on the way: serveExecute's chain-building extracted into
stageChain (start/wait/stderr) shared with the page endpoint —
behavior-preserving (integration suite green before touching pages).
Scope moved to 2c deliberately: head re-run without page reload, and
bar completion routed to /api/cursor for head stages — both belong to
the divider.

## 2026-08-19 (Wed) — serve Phase 2c: the split divider (Ref: DFC108)

The split proper. The explore artifact stays BYTE-IDENTICAL (2b's
property preserved): at load the page reads its own URL (?file= /
?pipeline= — which serve already puts there) and probes /api/health;
server mode reveals a head input fused above the tail bar
(🖥 [head] Run head ▸ → data.jsonl). Head runs server-side via the new
/api/execute?mode=buffered (JSON envelope — fetch can't read HTTP
trailers), result replaces vFS data.jsonl, local tail re-runs. Head
failures land loudly in the status line.

The star of the day is TestServeCutPointEquivalence — every cut of
three pipelines: head over HTTP, landed as data.jsonl, tail local,
compared to the whole pipeline run in one place. On its FIRST run it
caught two pre-existing wire-fidelity bugs:
1. Every `from` (and `tee`) ALPHABETIZED field order on output — a
   relic comment said "sorted for deterministic output" from the
   unordered-map era; records carry ordered schemas now, so the sort
   only destroyed information. tee out.jsonl → from out.jsonl has
   been scrambling column order for months. Fixed in
   writeWithInferredSchema, WriteJSONLWithInferredSchemaToWriter, and
   TeeFile (multi-file merge keeps its canonical sort — cross-file
   comparison genuinely needs one).
2. `update -set-expr` labeled numeric expression results "string" in
   the schema header (the split accidentally CORRECTED it, which is
   how the gate saw it). Fixed by pull-peeking the first output
   record and refining expr-field types before the header goes out.
Residual: sum-of-ints is float in-process but re-infers int after a
JSON hop — values identical; gate normalizes the header label like
the equivalence harness does.

Scope lesson re-learned: I also swapped root ReadJSON onto the fast
schema-aware reader as a drive-by — TestJSONComplexTypesRoundTrip
failed (legacy parses nested arrays/maps to []any/map; ParseJSONLine
uses JSONString). Reverted; the writer fixes carry the gate. TODO
updated: the remaining slow-reader sites now note BOTH semantic
blockers (array handling + nested types).

Explore harness: 26 scenarios (dormant standalone via getComputedStyle,
visible+prefilled in server mode, posts the head, feeds the tail, loud
failure — driven through a __srvFetch stub + the ?srvtest hook).
Full battery green: suite, equivalence, corpus, both harnesses,
doc-check, cut gate sabotage-verified. Deferred: head-input completion
via /api/cursor, optimizer-placed cuts.
