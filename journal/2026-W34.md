## 2026-08-20 (Thu) — head-input completion over HTTP (Ref: DFC108)

"lets try completion." The head input in the served workspace now has
the full completion/help stack — and it's the SAME machinery as
everywhere else: ssql-ui.js's completion section was restructured into
a factory, ssqlUIBindCompletion({input, exec, ready, schemaFields,
bigValueSource}), with the old #pipeline-over-wasm setup as the
default binding behind delegating globals (page contract unchanged).
Every executor call is awaited, so sync wasm and async HTTP executors
both work; async adds a staleness guard (drop answers if the caret
moved mid-flight). The explore template binds headInput with an HTTP
executor POSTing the cursor protocol to /api/cursor — so subcommands,
flags, operators, SERVER file paths, and sampled values complete in
the browser against the serve host. /api/cursor accepts an
ALLOW-LISTED env ({AUTOCLI_CACHE_FILE} only, anything else 400s) for
value sampling. Field-name slots fall back to a status hint in the
head (schema-mode pipelines over HTTP = future).

The await-ification broke ~25 harness scenarios at once — every
same-tick assertion raced the now-microtask popup. Fixed with a
settle() helper + awaitable triggers in both harnesses (mechanical
python transforms, then one straggler by hand). Enter-vs-completion
ordering in the head input: the completion binding registers first;
an arrow-activated accept preventDefaults Enter, and the run-head
listener respects e.defaultPrevented — a passive popup still lets
Enter run the head. Pinned by head-enter-still-runs.

Harnesses: playground 49 green, explore 30 (head-complete-popup /
-protocol / -accept, head-enter-still-runs). TestServeCursorEnv gates
the env allowlist (value completion works; PATH → 400). Embedded
ssql-ui.js copy refreshed.

## 2026-08-20 (Thu) — the pipe-ownership deadlock (found live by Ross)

Ross served /home/rossc/csvs and ran head `ssql from csv shuffled.csv
| ssql limit 10` — 1.2GB file, instant in a shell (0.015s), and the
serve chain HUNG (my repro curl died at the 5-minute timeout). Cause:
startStageChain wired stages with exec.StdoutPipe, whose read end the
PARENT keeps until Wait — so when limit exited after 10 rows, from
never got EPIPE (the parent still held the pipe), filled the 64KB
buffer, and blocked forever while wait() waited for it. A shell never
does this: children own pipe ends exclusively. Fix: explicit os.Pipe
per link, parent closes its copies right after Start; wait() gets
shell status semantics (last stage's error wins; upstream signal
deaths — SIGPIPE after early exit — are normal termination, detected
via ExitCode()==-1, no syscall import so wasm builds stay clean).
Repro now 0.024s. Pinned by TestServeExecuteEarlyExit (2MB fixture >>
pipe buffer; sabotage-verified by dropping the parent close).

Second footgun from the same session: clicking a huge file in the
index ran `from FILE | to explore` — the WHOLE 1.2GB materialized into
the page. Files >32MB now open with a VISIBLE `ssql limit 1000` head
stage (edit it to change; honest sampling, not silent truncation);
direct ?file= hits redirect to the same sampled form.

### Addendum: stale tail completion after head re-runs (found by Ross)

Second live find of the day: change the head to produce different
fields and the tail bar kept completing the OLD ones. The wasm tail's
schemaFieldsCache is keyed by upstream TEXT ("ssql from data.jsonl")
— correct when the vFS was immutable, wrong once head runs rewrite
data.jsonl under the same name (re-uploads had the same latent bug).
Fix: window.ssqlUISchemaCacheClear(), called from exploreRunHead,
ssqlUIWriteUpload, and after bar runs (tee'd files). Pinned by
head-refresh-invalidates-tail-fields (sabotage-verified); explore
harness at 32, playground still 49.
