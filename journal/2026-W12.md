### Pipeline Optimizer (`generate ssql`) — Phases 1–4

Implemented `generate ssql`, a pipeline optimizer that reads the same code fragments as `generate go`/`generate sql` and outputs a rewritten ssql pipeline that produces identical results but runs faster.

**File:** `cmd/ssql/commands/generate_ssql.go` (new), registered in `cmd/ssql/main.go`.

**12 active optimization rules across 4 phases:**

Phase 1 — SSH pushdown + pattern matching:
1. Adjacent where merge
2. SSH predicate pushdown (where → remote `--` args)
3. SSH aggregation pushdown (group-by → remote `--` args with `+`)
4. Sort + limit → top
5. Redundant sort elimination (sort before group-by)

Phase 2 — Catalog + predicate improvements:
6. Catalog predicate extraction (reads CSV header, moves matching where conditions to `-if`)
7. Catalog predicate pushdown (remaining where → remote `--` args)
8. Catalog aggregation pushdown (group-by → remote `--` args)
9. Predicate simplification (tighten ranges, detect contradictions)
10. Predicate reordering (cheap ops before expensive: eq → gt → contains → regex)

Phase 3 — Column pruning:
11. Parquet column pruning (analyze downstream fields, add `-columns` to `from parquet`)

Phase 4 — Join optimization:
12. Join predicate pushdown (split where by field ownership → left filter before join, right filter in `<(...)` process substitution)

**Rejected after benchmarking:**
- Mid-pipeline column dropping (insert `include` after `from csv`) — 1.5x SLOWER due to extra process overhead
- Limit pushdown past row-preserving commands — no effect due to Unix pipe backpressure

**Benchmarks (1M rows, Intel Core Ultra 9 275HX):**

| Rule | Speedup |
|---|---|
| Parquet 20→1 col + top | 14.8x |
| Parquet 20→3 cols | 5.1x |
| Join pushdown (both sides) | 3.4x |
| Predicate reorder (regex→eq) | 2.5x |
| Sort elimination | 2.4x |
| Sort + limit → top | 1.7x |

**Composability:** `generate ssql` output can be piped into `generate go` for optimize-then-compile workflows:
```bash
(export SSQLGO=1; ssql from catalog shards.csv | ssql where ... | ssql to table) \
  | ssql generate ssql | ssql generate go
```

**Flags:** `-run` (execute optimized pipeline), `-explain` (print applied rules to stderr).

**Documentation updated:**
- `doc/research/pipeline-optimizer.md` — full design doc with benchmarks
- `doc/cli-codelab.md` — added generate ssql and generate sql sections
- `README.md` — added optimizer examples to CLI section

### WASM Playground

Built a browser-based playground that runs the full ssql CLI via WebAssembly. No server needed — entirely client-side.

**Files:**
- `cmd/ssql-playground/main.go` — WASM entry point, exports `ssqlExec(args, stdin)` to JS, captures stdout/stderr via temp files (os.Pipe not available in WASM)
- `cmd/ssql-playground/playground.html` — UI with pipeline input, Run/Optimize/Generate Go/Generate SQL buttons, example pipelines, file upload
- `cmd/ssql-playground/fs-polyfill.js` — in-memory filesystem implementing the Node.js `fs` API that Go's `wasm_exec.js` expects. Loaded before `wasm_exec.js` to override the ENOSYS stubs. Supports open, read, write, close, stat, mkdir, unlink. `/dev/fd/` paths report as non-regular (FIFO) so join code generation detects process substitutions.

**Key findings during development:**
- `os.Pipe()` → "not implemented on js" — used temp files instead
- `os.WriteFile()` → "not implemented on js" — Go WASM's default `wasm_exec.js` stubs all fs ops with ENOSYS. Solved with `fs-polyfill.js` providing an in-memory filesystem
- `os.Args` is set once at WASM startup — must be updated before each `cmd.Execute()` for `getCommandString()` to produce correct fragment Command fields
- `/dev/fd/` paths must report as non-regular in stat so join's code generation creates `func` fragments (not simple file reads)
- Process substitution `<(...)` in SSQLGO mode must run inner pipeline with `-generate` flags to produce fragments, not data

**Features working:**
- All data commands (from csv, where, group-by, sort, join, window, top, etc.)
- Process substitution `<(ssql from ... | ssql where ...)` in joins
- Optimize button with explain output + "Use this pipeline" button
- Generate Go with proper func fragments for process substitutions
- Generate SQL with subqueries for process substitution joins
- File upload for user CSV files
- SSH/catalog pipelines gracefully handled (optimize works, run shows helpful message)

### Join Predicate Pushdown for Process Substitutions

Extended `ruleJoinPredicatePushdown` in the optimizer to handle `<(ssql from file.csv)` joins, not just plain file joins. Previously skipped when `JoinIsProcessSub` was true.

**How it works:**
- Parses func fragment's `FuncBody` to get inner pipeline commands
- Finds the `from` command in the inner pipeline to read file headers
- Classifies predicates by field ownership (left vs right source)
- Right-only predicates: appended as `where` to the inner pipeline
- Left-only predicates: inserted before the join (same as before)
- Renders modified `<(...)` with the injected where

**Example:**
```
ssql from orders.csv | ssql join <(ssql from customers.csv) -using customer_id | ssql where -if country eq US
→ ssql from orders.csv | ssql join <(ssql from customers.csv | ssql where -if country eq US) -using customer_id
```

### Expression Validation

Expressions referencing unknown fields now fail immediately with a clear error instead of the cryptic `invalid operation: <nil> * int`.

- `CompileExpr`: extracts identifiers from AST via `ast.Walk`, validates against record fields on first evaluation
- `CompileExprWithFields`: validates at compile time (fields known ahead of time)
- Expressions using `??`, `has()`, or `getOr()` skip validation (intentionally handle missing fields)
- Update command: expression errors now stop the pipeline (was: log and set empty string)

### WebVM: mobile touch keyboard bar

Added a touch-friendly button bar (Tab, Esc, |, <, >, (, ), Ctrl-C/D/Z) to the WebVM terminal for mobile devices. Android soft keyboards don't have Tab, which makes tab completion impossible.

**Key issues and fixes:**
- First attempt broke mobile boot — wrapping `onMount(initTerminal)` in an async function caused CheerpX init to fail silently on phones
