### Batched GPU Spectrogram

Implemented batched GPU FFT for spectrogram using `cufftPlanMany` to process all frames in a single GPU call, amortizing PCIe transfer overhead.

**CUDA kernel (gpu/sum.cu):**
- `applyWindowBatchKernel` - applies window function to all frames on GPU
- `gpuBatchedFFTMagnitude` - batched FFT using `cufftPlanMany` with batch=numFrames

**Go integration:**
- `gpu/gpu.go` - `BatchedFFTMagnitude()` CGo wrapper
- `gpu/gpu_stub.go` - Stub returning `ErrNotCompiled`
- `signal_gpu.go` - `batchedFFTMagnitudeGPU()` bridge
- `signal_stub.go` - Stub bridge

**GPU auto-selection:**
- Threshold: 32K total frame samples (`numFrames * windowSize`)
- Automatic fallback to CPU if GPU call fails

**Benchmark results (CPU, Intel Core Ultra 9 275HX):**
| Signal | Window | Time |
|--------|--------|------|
| 1s @ 44.1kHz | 256 | 12.3ms |
| 1s @ 44.1kHz | 1024 | 14.6ms |
| 1s @ 44.1kHz | 4096 | 15.3ms |
| 10s @ 44.1kHz | 1024 | 129ms |

The 10s case produces 1,718 frames (1.76M total samples), well above GPU threshold.
GPU benchmarks require CUDA hardware and `make gpu` rebuild.

### Docker GPU Build Fix

`make docker-gpu-extract` failed with `ERROR: BuildKit is enabled but the buildx component is missing or broken`. The Makefile was setting `DOCKER_BUILDKIT=1` which forces Docker through the buildx plugin path. On Docker 27.5+ BuildKit is the default builder, so the env var is unnecessary — and when buildx isn't installed, it causes a hard failure instead of falling back to the legacy builder.

**Fix:** Removed `DOCKER_BUILDKIT=1` from both `docker-gpu-image` and `docker-gpu-extract` targets.

**Files modified:**
- `Makefile` - Removed `DOCKER_BUILDKIT=1` from docker targets

## 2026-01-29 (Wednesday)

### AI Test Runner Bug Fixes

Fixed three bugs in test-ai-prompts.sh that prevented correct test execution.

**Bug 1: stdin consumption**
- `claude -p` was consuming stdin intended for the test parsing loop
- Result: Only 1 test per mode ran instead of 10
- Fix: Added `< /dev/null` to isolate claude's stdin from the loop

**Bug 2: Pattern starting with dash**
- `grep -qF "$pattern"` treated patterns like `-where age` as flags
- Result: `-w` interpreted as grep option, false negatives
- Fix: Added `--` before pattern argument to stop flag processing

**Bug 3: "or" alternative patterns**
- Patterns like `` `ssql.FFT(` or `ssql.FFTWithPhase(` `` were not split
- Result: Searched for literal string including "or", false negatives
- Fix: Split on "` or `" separator, test passes if ANY alternative matches

**Bug 4: Overly broad negative pattern**
- CLI-07's negative pattern `-expr` matched `-where-expr` and `-set-expr`
- Result: False positive - correct code marked as failing
- Fix: Changed to `where -expr` and `update -expr` (old usage patterns)

**Final results:** All 20 tests pass (10 Go, 10 CLI)
